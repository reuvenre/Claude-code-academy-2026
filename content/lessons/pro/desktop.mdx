Claude Code Desktop הוא הלשונית **Code** באפליקציית Claude ל-macOS,‏ Windows ו-Linux (בטא). הוא מריץ את אותו מנוע כמו ה-CLI, עם ממשק גרפי: סשנים מקבילים בסרגל הצד, panes של טרמינל, קבצים ו-diff, תצוגה מקדימה של האפליקציה ומשימות מתוזמנות. לא צריך טרמינל.

## למה זה חשוב
ב-CLI כל סשן מקבילי הוא טרמינל נפרד, ובדיקת שינויים היא `git diff`. ב-Desktop הכול בחלון אחד: רשימת סשנים בסרגל הצד, diff שאפשר להגיב על השורות שלו, ודפדפן מובנה שבו Claude מריץ את האפליקציה שלך ובודק את השינויים של עצמו. התיעוד הרשמי מסכם: Desktop מתאים לניהול סשנים מקבילים, סידור panes זה לצד זה ובדיקה חזותית של שינויים. ה-CLI מתאים לסקריפטים, לאוטומציה ולמי שמעדיף טרמינל.

באפליקציה יש שלוש לשוניות: **Chat** לשיחה רגילה בלי גישה לקבצים, **Cowork** לעבודה אוטונומית ארוכה, ו-**Code** לפיתוח. השיעור הזה עוסק רק ב-Code.

## איך מתקינים ומתחילים סשן ראשון?

<StepList>

1. מורידים את האפליקציה מ[דף ההתחלה הרשמי](https://code.claude.com/docs/en/desktop-quickstart): ל-macOS (Intel ו-Apple Silicon) או ל-Windows (x64, ויש גם מתקין ARM64). ב-Linux מתקינים עם apt, ראה בהמשך.
2. פותחים את Claude, מתחברים עם חשבון Anthropic ולוחצים על הלשונית **Code** במרכז למעלה. אם מופיעה בקשה לשדרג, צריך קודם מנוי בתשלום.
3. בוחרים **Local** ולוחצים **Select folder** כדי לבחור את תיקיית הפרויקט.
4. בוחרים מודל מהרשימה שליד כפתור השליחה. ההשוואה בין המודלים נמצאת ב[דף model-config](https://code.claude.com/docs/en/model-config).
5. בוחרים מצב הרשאה ליד כפתור השליחה, כותבים משימה ולוחצים **Enter**. למשל:
   ```text
   Find a TODO comment and fix it
   ```

</StepList>

אפשר לעצור את Claude בכל רגע עם כפתור העצירה, או להקליד תיקון וללחוץ **Enter** בלי לעצור. Claude קורא את התיקון כשהפעולה הנוכחית מסתיימת. `@` ואחריו שם קובץ מוסיף קובץ להקשר, ואפשר לצרף תמונות ו-PDF או לגרור קבצים לתיבת הפרומפט.

## איפה הסשן רץ?
את הסביבה בוחרים לפני ההודעה הראשונה, בתפריט הסביבות שבתיבת הפרומפט:

| סביבה | איפה Claude רץ | מתי לבחור |
| --- | --- | --- |
| **Local** | במחשב שלך, עם גישה ישירה לקבצים | ברירת המחדל לעבודה יומיומית |
| **Cloud** | בתשתית ענן, מנוהלת כברירת מחדל על ידי Anthropic | משימה ארוכה שצריכה להמשיך גם כשסוגרים את האפליקציה או מכבים את המחשב ([סשנים בענן](/pro/web)) |
| **SSH** | במכונה מרוחקת (Linux או macOS) שמתחברים אליה ב-SSH | הקוד יושב על שרת, VM בענן או dev container. ‏Desktop מתקין שם את Claude Code בחיבור הראשון |
| **WSL** (Windows) | בתוך הפצת WSL 2 | הריפו נמצא במערכת הקבצים של ההפצה |

## איזה מצב הרשאה לבחור?
מצב ההרשאה קובע כמה Claude עושה בלי לשאול. מחליפים אותו בכל רגע מהבורר שליד כפתור השליחה:

| מצב | מה קורה |
| --- | --- |
| **Manual** | Claude שואל לפני עריכת קבצים או הרצת פקודות. רואים diff ומאשרים או דוחים כל שינוי |
| **Accept edits** | עריכות קבצים ופקודות קבצים נפוצות מאושרות אוטומטית. פקודות טרמינל אחרות עדיין דורשות אישור |
| **Plan** | Claude קורא ומריץ פקודות כדי לחקור, ומציע תוכנית בלי לערוך קוד |
| **Auto** | Claude מבצע הכול, ובדיקות בטיחות ברקע חוסמות פעולות מסוכנות. מופיע רק כשהמצב זמין לך |
| **Bypass permissions** | בלי בקשות אישור, כמו `--dangerously-skip-permissions` ב-CLI. צריך להפעיל אותו קודם |

המצב שבוחרים נשמר לכל תיקייה, חוץ מ-Plan שחל רק על הסשן הנוכחי. ברירת מחדל לסשנים מקומיים חדשים מגדירים עם `permissions.defaultMode` ב[קובץ ההגדרות](/advanced/settings), כי Desktop קורא את אותם קובצי הגדרות כמו ה-CLI.

<Callout type="warning">
את Bypass permissions מפעילים רק בקונטיינר או ב-VM מבודד. ב-Pro וב-Max מפעילים אותו ב-Settings → Claude Code, וב-Team וב-Enterprise מדיניות הארגון שולטת בו.
</Callout>

## איך מריצים כמה סשנים במקביל?
לוחצים **+ New session** בסרגל הצד, או `Cmd+N` ב-macOS ו-`Ctrl+N` ב-Windows. כל סשן הוא שיחה עצמאית עם הקשר ושינויים משלו. `Ctrl+Tab` ו-`Ctrl+Shift+Tab` עוברים בין הסשנים.

- **בידוד עם worktree:** בריפו git בוחרים באפשרות **worktree** ליד שם ה-branch. הסשן מקבל עותק מבודד של הפרויקט דרך [git worktree](/pro/worktrees), ושינויים בו לא נוגעים בסשנים אחרים עד ה-commit. ברירת המחדל היא `<project-root>/.claude/worktrees/`.
- **שני סשנים זה לצד זה:** מחזיקים `Cmd` (או `Ctrl` ב-Windows) ולוחצים על סשן בסרגל הצד.
- **שאלת צד:** `Cmd+;` (או `Ctrl+;`), או `/btw` בתיבת הפרומפט, פותחים side chat שרואה את כל השיחה אבל לא מוסיף לה דבר.
- **משימות רקע:** ה-tasks pane מציג subagents, פקודות shell ברקע ו-[workflows](/pro/workflows) שרצים בסשן.
- **עבודה בין סשנים:** אפשר לבקש מ-Claude בשפה חופשית לבדוק מה סשן אחר עשה, לשלוח לו הודעה או לארכב אותו. לפני ארכוב Claude תמיד שואל.

האפליקציה שולחת התראת מערכת כשסשן מסיים משימה ואתה לא צופה בו.

## איך מסדרים את מרחב העבודה?
הלשונית Code בנויה מ-panes שגוררים לכל סידור: chat,‏ diff,‏ browser,‏ terminal,‏ file,‏ plan,‏ tasks ו-subagent, וב-macOS גם iOS Simulator. גוררים pane בכותרת שלו, ופותחים panes נוספים מתפריט **Views**.

- **טרמינל:** `` Ctrl+` `` פותח טרמינל בתיקיית הסשן, עם אותה סביבה ש-Claude רואה. זמין רק בסשנים מקומיים.
- **קבצים:** לחיצה על נתיב קובץ בשיחה או ב-diff פותחת אותו ב-file pane לעריכה קטנה ו-**Save**.
- **רמת פירוט:** `Ctrl+O` עובר בין Normal,‏ Thinking ו-Verbose. ‏Verbose מציג כל קריאה לכלי, שימושי כשרוצים להבין למה Claude עשה משהו.
- **קיצורים:** `Cmd+/` (או `Ctrl+/`) מציג את כל קיצורי המקלדת. קיצורי הטרמינל של ה-CLI, כמו `Shift+Tab`, לא חלים ב-Desktop.

## איך בודקים את השינויים לפני commit?
כש-Claude משנה קבצים מופיע מחוון כמו `+12 -1`. לוחצים עליו כדי לפתוח את ה-diff: רשימת קבצים בצד אחד והשינויים בצד השני.

<StepList>

1. לוחצים על שורה ב-diff, כותבים הערה ולוחצים **Enter**. חוזרים על זה לכמה שורות.
2. שולחים את כל ההערות יחד עם `Cmd+Enter` ב-macOS או `Ctrl+Enter` ב-Windows. ‏Claude מתקן ומציג diff חדש.
3. לחיצה על **Review code** מבקשת מ-Claude לסקור את השינויים בעצמו. הסקירה מתמקדת בשגיאות קומפילציה, שגיאות לוגיקה ודאיות, חולשות אבטחה ובאגים ברורים, ולא בסגנון או בעיצוב.

</StepList>

אחרי שפותחים PR, מופיע בסשן סרגל סטטוס של CI. המתג **Auto-fix** מנסה לתקן בדיקות שנכשלו, והמתג **Auto-merge** ממזג את ה-PR (squash) כשכל הבדיקות עוברות. זה דורש [GitHub CLI](https://cli.github.com/) (`gh`) מותקן ומחובר, ו-Auto-merge דורש גם הפעלה בהגדרות הריפו ב-GitHub.

## איך Claude רואה את האפליקציה שלך?
Claude מפעיל את שרת הפיתוח ופותח אותו ב-**Browser pane** כדי לבדוק את השינויים שלו: הוא מצלם מסך, בודק את ה-DOM, לוחץ, ממלא טפסים ומתקן בעיות שמצא. כברירת מחדל זה קורה אחרי כל עריכה (auto-verify). זה עובד גם לשרתי backend: Claude בודק endpoints וקורא לוגים.

את הגדרת השרת Claude שומר ב-`.claude/launch.json`. אם הפרויקט משתמש בפקודה אחרת, עורכים את הקובץ:

```json
{
  "version": "0.0.1",
  "configurations": [
    {
      "name": "my-app",
      "runtimeExecutable": "npm",
      "runtimeArgs": ["run", "dev"],
      "port": 3000
    }
  ]
}
```

כדי לכבות את הבדיקה האוטומטית מוסיפים `"autoVerify": false` ברמה העליונה של הקובץ. אל תשים סודות ב-`env` של הקובץ הזה, כי הוא נכנס לריפו. במקום זה משתמשים בעורך משתני הסביבה המקומי (גלגל השיניים ליד **Local** בתפריט הסביבות).

ה-Browser pane הוא גם דפדפן עם לשוניות: `Cmd+Shift+B` (או `Ctrl+Shift+B`) פותח אותו לתיעוד או לאתרים חיצוניים. בפעם הראשונה ש-Claude פועל באתר חיצוני, הוא מבקש אישור לאותו אתר. ה-Browser משתמש בפרופיל נקי, בלי הכניסות השמורות שלך. כשצריך ש-Claude יפעל בחשבונות המחוברים שלך, משתמשים ב-[Claude in Chrome](/pro/chrome).

## איך מתזמנים משימה חוזרת?
משימה מתוזמנת פותחת סשן חדש לבד בזמן ובתדירות שבוחרים, למשל code review כל בוקר. בלשונית Code לוחצים **Routines** בסרגל הצד, אחר כך **New routine**, ובוחרים **Local**. ממלאים שם, תיאור, הוראות (עם מצב הרשאה, מודל ותיקייה) ותזמון: Manual,‏ Hourly,‏ Daily,‏ Weekdays או Weekly. אפשר גם לבקש בשפה חופשית בכל סשן:

```text
set up a daily code review that runs every morning at 9am
```

| | [Routine בענן](/pro/routines) | משימה ב-Desktop | [`/loop`](/pro/scheduled) |
| --- | --- | --- | --- |
| רץ על | ענן | המחשב שלך | המחשב שלך |
| המחשב חייב להיות דלוק | לא | כן | כן |
| חייב סשן פתוח | לא | לא | כן |
| גישה לקבצים מקומיים | לא (clone חדש) | כן | כן |
| מרווח מינימלי | שעה | דקה | דקה |

<Callout type="warning">
משימה מקומית רצה רק כשהאפליקציה פתוחה והמחשב ער. אם המחשב ישן, ההרצה מדולגת, ובהתעוררות רצה הרצת השלמה אחת בלבד. אם התזמון חשוב, כתוב את זה בפרומפט עצמו. ובמצב Manual, הרצה שנתקלת בכלי בלי הרשאה נעצרת עד שתאשר. כדי למנוע את זה, לוחצים **Run now** אחרי היצירה ומאשרים "always allow" לכל כלי.
</Callout>

הפירוט המלא, כולל הרצות שהוחמצו וניהול משימות, ב[דף המשימות המתוזמנות](https://code.claude.com/docs/en/desktop-scheduled-tasks).

## ומה עם Linux,‏ WSL וסימולטור iOS?

### Linux (בטא)
האפליקציה ב-Linux נותנת את אותה חוויה של Chat,‏ Cowork ו-Code. היא דורשת Ubuntu 22.04 ומעלה או Debian 12 ומעלה, ומתקינים אותה ממאגר ה-apt של Anthropic, כך שעדכונים מגיעים עם עדכוני המערכת. computer use עוד לא זמין ב-Linux. פקודות ההתקנה ב[דף Linux הרשמי](https://code.claude.com/docs/en/desktop-linux).

### WSL ב-Windows
סשן WSL מריץ את Claude Code, את הכלים ואת git בתוך הפצת WSL 2, עם נתיבי Linux. בוחרים את ההפצה בתפריט הסביבות. זה מתאים כשהריפו נמצא במערכת הקבצים של ההפצה, כי גישה אליו מ-Windows איטית ושוברת file watching. דרוש WSL 2 (לא WSL 1) ו-git בתוך ההפצה. הטרמינל המובנה, connectors ו-plugins,‏ ה-file pane והשלמת `@` עוד לא זמינים בסשן WSL. פרטים ב[דף WSL הרשמי](https://code.claude.com/docs/en/desktop-wsl).

### סימולטור iOS (macOS, בטא ציבורית)
כש-Claude בונה ומריץ אפליקציית iOS בסימולטור, ה-**iOS Simulator pane** נפתח לבד ומזרים את מסך המכשיר. הוא לא צריך computer use ולא משתלט על המסך. דרוש Mac עם Xcode ופלטפורמת iOS, והוא עובד רק בסשנים מקומיים. מנסחים את המשימה סביב הרצה ובדיקה:

```text
Build the app and run it in the simulator to check the onboarding flow.
```

בפעם הראשונה ש-Claude משתמש במכשיר מדומה, האפליקציה מבקשת אישור. Claude שולט רק במכשירים מדומים, לא ב-iPhone או ב-iPad פיזי. פרטים ב[דף הסימולטור הרשמי](https://code.claude.com/docs/en/desktop-ios-simulator).

## איך עוברים בין ה-CLI ל-Desktop?
מעבירים סשן מהטרמינל לאפליקציה עם:

<CommandBlock>/desktop</CommandBlock>

Claude שומר את הסשן, פותח אותו ב-Desktop ויוצא מה-CLI. הפקודה זמינה ב-macOS וב-Windows x64 כשמחוברים עם מנוי Claude. היא לא זמינה עם אימות במפתח API, ולא ב-Amazon Bedrock,‏ Google Cloud's Agent Platform או Microsoft Foundry. בכיוון ההפוך, מקלידים `/resume` בתיבת הפרומפט של Desktop ובוחרים סשן שהתחיל ב-CLI.

שני הממשקים קוראים את אותם קבצים, כך שההגדרה שלך עוברת: [CLAUDE.md](/beginner-plus/claude-md),‏ [שרתי MCP](/advanced/mcp) ב-`~/.claude.json` או `.mcp.json`,‏ hooks,‏ skills והגדרות ב-`~/.claude/settings.json`.

<Callout type="note">
ב-Desktop אין `--print` וסקריפטים, אין [agent teams](/pro/agent-teams) ואין מצב `dontAsk`. לאוטומציה ולסקריפטים נשארים ב-CLI.
</Callout>
