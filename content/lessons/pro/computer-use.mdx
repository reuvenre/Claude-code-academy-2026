Computer use מאפשר ל-Claude Code לפתוח אפליקציות, ללחוץ, להקליד ולראות את המסך, כמו שאתה עובד. ב-CLI הוא זמין ב-macOS בלבד, כ-research preview, בתוכניות Pro ו-Max. מפעילים את השרת המובנה `computer-use` דרך `/mcp`, ומאשרים כל אפליקציה בנפרד בכל סשן.

## למה זה חשוב
Computer use סוגר את הפער בין כתיבת קוד לבדיקה שלו בממשק גרפי. באותה שיחה שבה Claude כתב את הקוד, הוא יכול לקמפל אפליקציה, להפעיל אותה, ללחוץ על הכפתורים ולצלם את התוצאה. התיעוד הרשמי מביא ארבעה שימושים:

- **בנייה ובדיקה של אפליקציות native:** Claude כותב, מקמפל, מפעיל ולוחץ על כל פקד כדי לוודא שהוא עובד.
- **בדיקות UI מקצה לקצה:** Claude פותח אפליקציית Electron מקומית ועובר על תהליך ההרשמה, בלי להגדיר Playwright.
- **דיבאג של בעיות תצוגה:** Claude משנה את גודל החלון, משחזר את הבאג, מצלם אותו ומאמת את התיקון.
- **כלים עם ממשק גרפי בלבד:** כלי עיצוב, לוחות בקרה של חומרה, ה-iOS Simulator ואפליקציות בלי CLI או API.

<Callout type="note">
Computer use הוא research preview. ב-CLI הוא דורש macOS ותוכנית Pro או Max, ולא זמין בתוכניות Team או Enterprise. הוא דורש סשן אינטראקטיבי, ולכן לא עובד במצב לא-אינטראקטיבי עם הדגל `-p`.
</Callout>

## מתי Claude משתמש ב-computer use?
רק כששום כלי מדויק יותר לא מתאים. Computer use הוא הדרך הרחבה והאיטית ביותר, ולכן Claude בודק קודם את האפשרויות האחרות:

| המשימה | הכלי ש-Claude בוחר |
| --- | --- |
| יש [שרת MCP](/advanced/mcp) לשירות | שרת ה-MCP |
| פקודת shell | Bash |
| עבודה בדפדפן, ו-Claude in Chrome מוגדר | [Claude in Chrome](/pro/chrome) |
| אף אחד מאלה | computer use |

בפועל, שליטה במסך שמורה לאפליקציות native, לסימולטורים כמו ה-iOS Simulator ולכלים בלי API.

## איך מפעילים computer use?
Computer use הוא שרת MCP מובנה בשם `computer-use`, והוא כבוי כברירת מחדל.

<StepList>

1. בסשן אינטראקטיבי של Claude Code מריצים `/mcp` ומוצאים את `computer-use` ברשימה. הוא מופיע כ-disabled.
2. בוחרים `computer-use` ואז **Enable**. ההגדרה נשמרת לכל פרויקט בנפרד, כך שעושים את זה פעם אחת בכל פרויקט.
3. בפעם הראשונה ש-Claude מנסה להשתמש במחשב, מופיעה בקשה לשתי הרשאות macOS: **Accessibility** (לחיצות, הקלדה וגלילה) ו-**Screen Recording** (לראות את המסך). מאשרים את שתיהן דרך הקישורים ל-System Settings, ובוחרים **Try again**.

</StepList>

ייתכן ש-macOS ידרוש להפעיל מחדש את Claude Code אחרי אישור Screen Recording.

אחרי ההגדרה מבקשים משימה שצריכה ממשק גרפי. הדוגמה מהתיעוד:

```text
Build the app target, launch it, and click through each tab to make
sure nothing crashes. Screenshot any error states you find.
```

## איך מאשרים אפליקציות?
הפעלת השרת לא נותנת גישה לכל האפליקציות. בפעם הראשונה ש-Claude צריך אפליקציה מסוימת בסשן, מופיעה בקשה בטרמינל שמציגה:

- אילו אפליקציות Claude רוצה לשלוט בהן.
- הרשאות נוספות, כמו גישה ל-clipboard.
- כמה אפליקציות אחרות יוסתרו בזמן העבודה.

בוחרים **Allow for this session** או **Deny**. האישור תקף לסשן הנוכחי בלבד, ואפשר לאשר כמה אפליקציות יחד.

אפליקציות עם גישה רחבה מקבלות אזהרה נוספת:

| אזהרה | חלה על |
| --- | --- |
| Equivalent to shell access | Terminal,‏ iTerm,‏ VS Code,‏ Warp וטרמינלים ו-IDEs אחרים |
| Can read or write any file | Finder |
| Can change system settings | System Settings |

האפליקציות האלה לא חסומות. האזהרה עוזרת להחליט אם המשימה מצדיקה את רמת הגישה. כדי ש-Claude ילחץ על שולחן העבודה, על ה-Dock או על חלון Finder, צריך לאשר את Finder.

רמת השליטה משתנה גם לפי סוג האפליקציה: בדפדפנים ובפלטפורמות מסחר Claude רק צופה, בטרמינלים וב-IDEs הוא רק לוחץ וגולל (בלי הקלדה וקיצורי מקלדת), ובשאר האפליקציות יש לו שליטה מלאה. הפירוט המלא נמצא ב[תיעוד של Desktop](https://code.claude.com/docs/en/desktop#app-permissions).

## מה קורה על המסך בזמן העבודה?

### סשן אחד בכל פעם
רק סשן אחד יכול להשתמש במחשב. הסשן לוקח נעילה בפעולת computer use הראשונה שלו, ומשחרר אותה כשהסשן נסגר, לא כשהמשימה מסתיימת. סשן שני יקבל שגיאה עם שם הסשן שמחזיק בנעילה. אם הסשן שמחזיק בנעילה קרס, הנעילה משתחררת אוטומטית.

### אפליקציות אחרות מוסתרות
כש-Claude מתחיל לשלוט במסך, שאר האפליקציות הגלויות מוסתרות, כדי שהוא יעבוד רק עם האפליקציות שאושרו. חלון הטרמינל נשאר גלוי אבל לא נכלל בצילומי המסך, כך שאתה צופה ו-Claude לא רואה את הפלט של עצמו. בסוף התור האפליקציות חוזרות אוטומטית.

### צילומי מסך מוקטנים אוטומטית
Claude Code מקטין כל צילום מסך לפני שהוא נשלח למודל, תוך שמירה על יחס הגובה-רוחב. אין צורך להוריד רזולוציה במסכי Retina, ואין הגדרה לשינוי הגודל. אם טקסט או פקדים קטנים מדי ל-Claude, מגדילים אותם באפליקציה עצמה.

### עוצרים בכל רגע
בפעם הראשונה בכל תור מופיעה התראת macOS עם הטקסט "Claude is using your computer · press Esc to stop." לוחצים `Esc` בכל מקום, או `Ctrl+C` בטרמינל. Claude עוצר, מחזיר את האפליקציות שהוסתרו ומחזיר לך את השליטה. התראה שנייה מופיעה כש-Claude מסיים.

## מה צריך לדעת על אבטחה?
Computer use רץ על שולחן העבודה האמיתי שלך, עם גישה לאפליקציות שאישרת. זה שונה מכלי Bash, שיכול לרוץ ב-[sandbox](/advanced/permissions-sandbox).

<Callout type="warning">
גבול האמון כאן שונה. Claude בודק כל פעולה ומסמן חשד ל-prompt injection מתוכן שמופיע על המסך, אבל הוא עובד על המחשב האמיתי. אשר רק את האפליקציות שהמשימה באמת צריכה, וקרא את [מדריך הבטיחות הרשמי](https://support.claude.com/en/articles/14128542).
</Callout>

ההגנות המובנות פועלות בלי הגדרה:

- **אישור לכל אפליקציה:** Claude שולט רק באפליקציות שאישרת בסשן הנוכחי.
- **אזהרות מיוחדות:** אפליקציות עם גישה ל-shell, לקבצים או להגדרות מערכת מסומנות לפני האישור.
- **הטרמינל מחוץ לצילומים:** Claude לא רואה את חלון הטרמינל, כך שטקסט בסשן לא חוזר למודל.
- **Esc גלובלי:** המקש עוצר מכל מקום, והלחיצה נבלעת, כך ש-prompt injection לא יכול להשתמש בה כדי לסגור חלונות דו-שיח.
- **קובץ נעילה:** רק סשן אחד שולט במחשב בכל רגע.

## איך זה נראה בעבודה אמיתית?
נניח שבאג תצוגה מופיע רק בחלון צר. במקום לשחזר אותו ידנית, מבקשים מ-Claude, כמו בדוגמה מהתיעוד:

```text
The settings modal clips its footer on narrow windows. Resize the app
window down until you can reproduce it, screenshot the clipped state,
then check the CSS for the modal container.
```

Claude מקטין את החלון, מצלם את המצב השבור וקורא את קובצי ה-CSS הרלוונטיים. באותה דרך אפשר לבקש ממנו להפעיל את ה-iOS Simulator ולעבור על מסכי ה-onboarding, בלי לכתוב XCTest.

## מה ההבדל בין ה-CLI לאפליקציית Desktop?
שני הממשקים משתמשים באותו מנוע computer use, עם כמה הבדלים:

| תכונה | Desktop | CLI |
| --- | --- | --- |
| פלטפורמות | macOS ו-Windows | macOS בלבד |
| הפעלה | מתג ב-**Settings > General** (תחת **Desktop app**) | הפעלת `computer-use` ב-`/mcp` |
| רשימת אפליקציות חסומות | ניתנת להגדרה | עדיין לא זמינה |
| החזרת אפליקציות מוסתרות | אופציונלית | תמיד פעילה |

ב-Windows משתמשים ב-[computer use של Desktop](https://code.claude.com/docs/en/desktop#let-claude-use-your-computer).

<Callout type="warning">
אם `computer-use` לא מופיע ב-`/mcp`, בדוק: macOS, תוכנית Pro או Max (מוודאים עם `/status`), התחברות דרך claude.ai ולא דרך ספק חיצוני כמו Amazon Bedrock, וסשן אינטראקטיבי בלי `-p`.
</Callout>
