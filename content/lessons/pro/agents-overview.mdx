ל-Claude Code יש חמש דרכים לעבוד על כמה משימות במקביל: subagents,‏ agent view,‏ agent teams,‏ dynamic workflows ו-projects. הן נבדלות במי שמתאם את העבודה (אתה, Claude או סקריפט), בכמה אתה מעורב, ובשאלה אם העבודה רצה על המחשב שלך או בענן.

## למה זה חשוב
כל הגישות מריצות סשנים של Claude, אבל הן פותרות בעיות שונות. בחירה לא נכונה עלולה להוביל לשיחה ראשית מוצפת בלוגים, לסוכנים שעורכים את אותם קבצים, או לניהול ידני של הרבה סשנים שהיה אפשר להשאיר ל-Claude. השיעור הזה הוא מפה לרמה כולה. כל גישה מקבלת שיעור משלה בהמשך.

## מה ההבדל בין חמש הגישות?
זו הטבלה המרכזית מהתיעוד הרשמי, בתרגום מקוצר:

| גישה | מה מקבלים | מתי להשתמש |
| --- | --- | --- |
| **Subagents** | עובדים בתוך סשן אחד שמבצעים משימה צדדית בהקשר משלהם ומחזירים סיכום | משימה צדדית הייתה מציפה את השיחה בתוצאות חיפוש, לוגים או תוכן קבצים שלא תחזור אליהם |
| **Agent view** | מסך אחד לשליחה ולמעקב אחרי סשנים שרצים ברקע, נפתח עם `claude agents`. ‏Research preview | יש לך כמה משימות עצמאיות, ואתה רוצה להעביר אותן, לראות מצב במבט אחד ולהתערב רק כשצריך |
| **Agent teams** | כמה סשנים מתואמים עם רשימת משימות משותפת והודעות בין הסוכנים, בניהול lead. ניסיוני וכבוי כברירת מחדל | אתה רוצה ש-Claude יפרק פרויקט לחלקים, יחלק אותם ויסנכרן בין העובדים |
| **Projects** | שיחה מתמשכת אחת ב-claude.ai/code או באפליקציית הדסקטופ. Claude פותח סשנים מקבילים בענן (threads), נותן לכל אחד את הריפו, ההנחיות והזיכרון של הפרויקט, ומראה לך מי צריך אותך. בטא ציבורית ב-Pro,‏ Max | העבודה משתרעת על משימות רבות לאורך ימים או שבועות, צריכה להמשיך כשהמחשב כבוי, ועדיף לך לתאר אותה פעם אחת |
| **Dynamic workflows** | סקריפט שמריץ subagents רבים ומצליב את התוצאות שלהם | העבודה גדולה מכמה subagents, או שצריך לאמת ממצאים זה מול זה: audit לכל הקוד, מיגרציה של 500 קבצים, מחקר מוצלב |

בכל הגישות העובדים הם סשנים של Claude. כדי לשלב כלי אחר, חושפים אותו ל-Claude כ-[MCP server](/advanced/mcp).

<Callout type="warning">
הרצה של כמה סשנים או subagents בו-זמנית מכפילה את צריכת הטוקנים. פרטים ב-[Costs](https://code.claude.com/docs/en/costs) ובשיעור [עלויות והקשר](/beginner-plus/costs-context).
</Callout>

## איך בוחרים גישה?
ההחלטה נשענת על שלוש שאלות: מי מתאם, האם העובדים מדברים ביניהם, והאם הם נוגעים באותם קבצים.

### מי מתאם את העבודה?
- **Claude מאציל ואוסף תוצאות בתוך שיחה אחת:** subagents.
- **אתה מעביר משימות עצמאיות וחוזר לבדוק אחר כך:** agent view.
- **Claude מתכנן, מחלק ומפקח על קבוצת עובדים:** agent teams (ניסיוני וכבוי כברירת מחדל).
- **סקריפט מחזיק את התוכנית, ולא שיקול הדעת של Claude בכל תור:** dynamic workflows.

### האם העובדים צריכים לדבר ביניהם?
- subagents מדווחים רק לשיחה שהפעילה אותם.
- סשנים מ-agent view מדווחים רק לך.
- teammates ב-agent team מתכתבים ישירות, וכשיש להם את כלי ה-Task הם חולקים גם רשימת משימות.
- בין סשנים שאתה מריץ בעצמך, כולל אלה שנשלחו מ-agent view, אפשר להעביר ממצאים עם [cross-session messaging](/pro/cross-session).

### האם המשימות נוגעות באותם קבצים?
מבודדים את העבודה עם [worktrees](/pro/worktrees), כך שלכל סשן יש עותק git נפרד. subagents וסשנים שאתה מריץ בעצמך יכולים כל אחד לקבל worktree משלו. סשן שנשלח מ-agent view עובר ל-worktree משלו לפני שהוא עורך קבצים.

<Callout type="warning">
agent teams לא מבודד teammates ב-worktrees. מחלקים את העבודה כך שכל teammate אחראי על סט קבצים אחר.
</Callout>

## אילו כלים תומכים בעבודה במקביל בלי להיות גישה בפני עצמם?
- **Worktrees:** עותק git נפרד לכל סשן, כדי שסשנים מקבילים לא יערכו את אותם קבצים.
- **Cross-session messaging:** מאפשר ל-Claude להציג רשימה של שאר הסשנים שלך ב-Claude Code ולשלוח להם הודעות, על המחשב הזה, על מחשב אחר או בענן, כך שסשנים שאתה מריץ בעצמך יכולים להעביר ביניהם ממצאים וסטטוס.
- **`/batch`:** skill שבו Claude מפצל שינוי גדול אחד ל-5 עד 30 subagents מבודדים ב-worktrees, שכל אחד פותח pull request. זה שימוש ארוז ב-subagents וב-worktrees, לא סגנון תיאום נפרד.

יש גם יכולות שמריצות את Claude בלי שתנהל כל צעד, אבל הן פותרות בעיה אחרת:

| יכולת | מה היא עושה |
| --- | --- |
| background bash command | מריצה פקודת shell אחת בלי לחסום את השיחה. לא יוצרת סוכן |
| forked subagent | subagent שיורש את כל הקשר השיחה במקום להתחיל נקי. מפעילים עם `/subtask` |
| `/fork` | מעתיק את כל הסשן לסשן רקע חדש שרץ לצדו |
| routine | מריץ סשן לפי לוח זמנים בענן, לא במקביל על המחשב שלך |

<Callout type="note">
כש-agent view כבוי, הפקודה ל-forked subagent היא `/fork`, ו-`/subtask` לא זמינה.
</Callout>

## איך בודקים מה רץ כרגע?
הפקודה תלויה בגישה:

| מה רץ | איך בודקים |
| --- | --- |
| סשנים ברקע | `claude agents` פותח את agent view: כל הסשנים, המצב שלהם ומי צריך אותך |
| subagents בסשן הנוכחי | subagents ברקע שיש להם שם מופיעים עם הסטטוס שלהם ברשימת ההשלמה של `@` |
| כל מה שרץ ברקע בסשן הנוכחי | `/tasks` מציג כל פריט ומאפשר לבדוק, להתחבר או לעצור. כולל subagents שסיימו |
| dynamic workflows | `/workflows` מציג ריצות פעילות ושהסתיימו, באיזה שלב כל אחת וכמה סוכנים סיימו |

<Callout type="warning">
`/agents` ו-`claude agents` הם שני דברים שונים. ‏`claude agents` פותח את agent view. ‏`/agents` בתוך סשן לא פותח פאנל, אלא מדפיס הודעה שמפנה למיקום קובצי ה-subagents.
</Callout>

## דוגמה מעשית
שלושה מצבים, שלוש בחירות:

- **"מצא איפה מטופלת ההתחברות בקוד":** החיפוש ייצר הרבה פלט שלא תצטרך. subagent יחזיר רק סיכום.
- **שלושה באגים לא קשורים:** שולחים כל אחד כסשן מ-agent view, ממשיכים לעבוד, וחוזרים רק לסשן שמסומן כצריך אותך.
- **audit אבטחה לכל הקוד, עם אימות הממצאים:** זו עבודה גדולה מכמה subagents ודורשת הצלבה, ולכן מתאים dynamic workflow.
