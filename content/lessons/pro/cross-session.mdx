Claude מעביר הודעת טקסט מסשן אחד שלך לסשן אחר: הוא מוצא את היעד עם הכלי `ListAgents` ושולח עם `SendMessage`. אתה רק מבקש במילים, למשל "תשאל את הסשן בטרמינל השני אם ה-migration הסתיים", או מזכיר סשן עם `@`. עובר רק הטקסט, לא השיחה או הקבצים.

## למה זה חשוב
כשכמה סשנים עובדים במקביל, מה שקורה באחד משפיע על השני. בלי הודעות אתה מעתיק ממצאים בין טרמינלים בעצמך. עם cross-session messaging, ‏Claude יכול להזהיר סשן אחר כששינוי שלו שובר את מה שהסשן ההוא בונה, או להעביר תשובה לשאלה שהסשן השני תקוע עליה. Claude יכול לשלוח הודעה גם מיוזמתו, כשהוא מזהה צורך.

כשהסשן עומד בדרישות, הפיצ'ר פועל בלי שום הגדרה.

## מתי משתמשים בזה, ומתי בכלי אחר?
משתמשים בהודעות בין סשנים עצמאיים שאתה פותח ומנווט בעצמך. המקרים הנפוצים לפי התיעוד:

- **העברת ממצא:** סשן אחד גילה breaking change או קיבל החלטה, ו-Claude מסכם אותה לסשן שעובד על האזור המושפע.
- **תיאום worktrees מקבילים:** סשנים שעובדים על אותו ריפו ב-[worktrees](/pro/worktrees) נפרדים מעדכנים זה את זה מה נכנס.
- **סטטוס מעבודה ארוכה:** migration או הרצת בדיקות מדווחים לסשן שאתה מסתכל עליו.
- **בין מכונות:** הודעה לסשן שלך במחשב אחר או בענן.

לכל צורך אחר יש פיצ'ר ייעודי:

| הצורך | הכלי |
| --- | --- |
| להמשיך שיחה בטרמינל אחר או להעביר את כל ההקשר שלה | [resume לסשן](/beginner-plus/sessions) |
| צוות סשנים ש-Claude פותח ומפקח עליו | [Agent teams](/pro/agent-teams) |
| לצפות בהרבה סשנים ולנווט אותם ממקום אחד | [Agent view](/pro/agent-view) |
| לנווט סשן בעצמך מהטלפון או ממכשיר אחר | [Remote Control](https://code.claude.com/docs/en/remote-control) |
| לדחוף אירועים חיצוניים, כמו תוצאות CI, לתוך סשן | [Channels](https://code.claude.com/docs/en/channels) |

## איך מבקשים מ-Claude לשלוח הודעה?
כותבים מה הסשן השני צריך לדעת או לעשות. לא קוראים לכלים בעצמך, ו-Claude כותב את נוסח ההודעה. אלה דוגמאות מהתיעוד לפרומפטים שאתה מקליד:

```text
Ask the session running in my other terminal whether the migration finished
```

```text
Explain what we just did to the session working on the payments API
```

כדי לבחור את היעד בעצמך, מקלידים `@` ואת האותיות הראשונות של שם הסשן, ובוחרים מהרשימה הנפתחת, כמו שמזכירים subagent:

```text
Let @api-worker know the schema migration finished
```

- הרשימה הנפתחת מציגה את הסשנים החיים שלך במכונה הזו. סשן ענן או Remote Control מופיע בה רק אחרי ש-Claude כבר הציג או שלח הודעה לסשנים מחוץ למכונה, אז קודם מבקשים מ-Claude להציג אותם.
- שם עם רווח או תווים שאינם אותיות, ספרות, מקפים או קווים תחתונים כותבים במירכאות כפולות, כמו `@"release notes"`.
- אם כמה סשנים חיים עונים לאותו שם, Claude שואל אותך למי התכוונת לפני השליחה.

## איך מגיעה ההודעה לסשן השני?
ה-Claude המקבל קורא את ההודעה בין קריאות לכלים, כך שכלי שרץ לא נקטע. אם הסשן המקבל פנוי (idle), ‏Claude Code פותח turn חדש עם ההודעה.

בסשן המקבל ההודעה מופיעה כשורת תצוגה מקדימה עמומה עם שם השולח והשורה הראשונה, למשל `› Message from @api-worker: Schema migration finished (ctrl+o to expand)`. לוחצים `Ctrl+O` כדי לקרוא את הטקסט המלא. Claude קורא את ההודעה המלאה בכל מקרה. הודעה שנמסרה נספרת בשימוש כמו פרומפט שהקלדת, וה-Claude המקבל יכול לענות לשולח באותה דרך, חוץ מהודעה חד-כיוונית בין מכונות שהגיעה בלי כתובת תשובה.

`@` בתוך טקסט ההודעה לא מצרף קובץ או משאב MCP בצד המקבל. Claude רואה את האזכור כפי שנכתב, ויכול לפתוח את הנתיב בכלים שלו לפי ההרשאות של הסשן שלו.

## מה הודעה מסשן אחר לא יכולה לעשות?
Claude Code אומר ל-Claude המקבל שההודעה הגיעה מסשן אחר ולא ממך, ומגביל אותה:

- **לא מאשרת כלום:** היא לא נחשבת להסכמה שלך ולא עונה על בקשת הרשאה ממתינה.
- **לא משנה הגדרות:** Claude מונחה לא לשנות הגדרות הרשאות, `CLAUDE.md` או תצורה אחרת בגלל בקשה מסשן אחר.
- **פקודות לא רצות:** פקודה בטקסט, כמו `/compact`, מגיעה כטקסט רגיל.
- **בקשות הרשאה ממשיכות לקפוץ:** אם הפעולה דורשת הרשאה שאין לסשן המקבל, תראה את אותה בקשת אישור כרגיל.

גבולות ההרשאות נשארים לכל סשן בנפרד. Claude מונחה לא לבקש מסשן אחר פעולה שנחסמה או נדחתה אצלו, ולהחזיר אותה אליך.

## איך רואים לאילו סשנים אפשר להגיע?
Claude מוצא את היעד לבד, אבל כדי לראות בעצמך מריצים:

<CommandBlock>/list-agents</CommandBlock>

הפקודה זמינה גם בשם `/peers`. השורה הראשונה, כשהיא מופיעה, היא השם של הסשן הנוכחי. מתחתיה:

| שורה | מה זה |
| --- | --- |
| Subagents | סוכנים שרצים בתוך הסשן הנוכחי |
| Teammates | חברי ה-agent team של הסשן הזה |
| סשנים מקומיים | סשנים אחרים שלך באותה מכונה, כולל background sessions |
| `cloud` | סשני הענן שלך, כשהסשן מחובר ל-Remote Control |
| `Remote Control` | סשנים שלך במכונות אחרות, כשהסשן מחובר ל-Remote Control |

סשן עונה לשם שקבעת עם `/rename` או עם הדגל `--name`. אם לא קבעת, Claude Code בוחר שם בעצמו. שמות ברורים עוזרים לך ול-Claude לכוון את ההודעה לסשן הנכון.

<CommandBlock>claude --name api-worker</CommandBlock>

## איך מקבלים התראה כשסשן אחר מסיים?
מבקשים מ-Claude, ו-Claude מבקש מהסשן השני לשלוח התראה אחת כשהוא עובר למצב idle (סיים turn ואין לו משהו בתור) או נסגר:

```text
Tell me when the migration session finishes what it's working on
```

הרשמה שנשלחת בלי הודעה מצורפת לא פותחת turn ולא צורכת טוקנים בסשן הנצפה. ההתראה חד-פעמית, ואף סשן לא בודק את השני שוב ושוב. אם לא הגיעה התראה תוך 12 שעות, ההרשמה מבוטלת ו-Claude מקבל על כך הודעה. זה עובד רק מהשיחה הראשית ורק מול סשנים שלך באותה מכונה.

## איך שולטים בהודעות נכנסות?
ההגדרה [`crossSessionInbound`](https://code.claude.com/docs/en/settings-reference#crosssessioninbound) קובעת מה סשן עושה עם הודעות מהסשנים האחרים שלך:

| ערך | התנהגות |
| --- | --- |
| `accept` | כל הודעה נמסרת ל-Claude |
| `hold` | מוצגת הודעה על כל הודעה נכנסת, בלי למסור אותה ל-Claude |
| `refuse` | ההודעה נזרקת בלי להימסר |

אפשר גם לבחור את הערך ב-`/config`, בשורה **Messages from your other sessions**. הבחירה נשמרת ב-user settings.

כשלא הוגדר ערך, Claude Code מחליט לפי מצבי ההרשאות של שני הסשנים. סשן שמבקש אישורים מקבל הודעות, ומעכב לאישורך רק הודעה מסשן שעוקף בקשות הרשאה. סשן שעוקף בקשות הרשאה מעכב כל הודעה לאישורך, חוץ מהודעה מסשן שעוקף גם הוא. הודעה מעוכבת פותחת חלון אישור עם **Approve** או **Deny**. פרטים על מצבי ההרשאות בשיעור [מצבי הרשאות](/beginner-plus/permission-modes).

<Callout type="note">
סשן `claude -p` מקבל הודעות כמו סשן אינטראקטיבי, אבל לא יכול להציג חלון אישור. כדי ש-worker כזה יקבל הודעות בלי השגחה, מפעילים אותו עם `crossSessionInbound` בערך `accept` בתוך `--settings`. סשן ב-bare mode לא מקבל הודעות בכלל.
</Callout>

## איך שולחים הודעות לסשנים במכונות אחרות?
הדרך שבה ההודעה עוברת תלויה במקום שבו הסשן היעד רץ:

| איפה הסשן השני | איך ההודעה עוברת |
| --- | --- |
| באותה מכונה | דרך socket לכל סשן (macOS ו-Linux) או named pipe (Windows), אף פעם לא דרך השרתים של Anthropic |
| במכונה אחרת שלך | דרך השרתים של Anthropic, בחיבור ה-Remote Control של המכונה ההיא |
| בענן | דרך השרתים של Anthropic, ישירות לסשן הענן |

כדי למצוא סשנים מחוץ למכונה, הסשן השולח צריך להיות מחובר ל-[Remote Control](https://code.claude.com/docs/en/remote-control) עם התחברות claude.ai. אם הוא לא מחובר, ההודעה עדיין נשלחת אבל בלי כתובת תשובה, כך שהצד השני לא יכול לענות.

סשן בתוך container לא מגיע לסשן על המחשב המארח, וסשן בתוך WSL 2 לא מגיע לסשן Windows רגיל באותו מחשב. שני הצדדים צריכים לראות את אותם קבצים.

כדי לדרוש את אישורך לפני שהודעה יוצאת מהמכונה, גם במצב `bypassPermissions`:

```json
{
  "isolatePeerMachines": true
}
```

## איך מכבים את הפיצ'ר?
קבלה ושליחה נשלטות בנפרד:

- **להפסיק לקבל:** `crossSessionInbound` בערך `refuse`.
- **להפסיק לשלוח ולהציג סשנים:** [deny rules](/advanced/permissions-sandbox) ל-`SendMessage` ול-`ListAgents`, בשם הכלי בלבד.

מנהלים יכולים לכבות את שני הכיוונים לכל הארגון ב-managed settings:

```json
{
  "permissions": {
    "deny": ["SendMessage", "ListAgents"]
  },
  "crossSessionInbound": "refuse"
}
```

<Callout type="warning">
חסימת `SendMessage` מבטלת גם הודעות ל-subagents ולחברי agent team, כי זה אותו כלי. וסשן שמסרב להודעות לא נראה אחרת ב-`/status` או ברשימות של סשנים אחרים. כדי לוודא שהוא מסרב, בודקים את קובצי ההגדרות שחלים עליו.
</Callout>

## איך בודקים שהפיצ'ר זמין?
מקלידים `/list-agents`:

- **הפקודה לא מוכרת:** לסשן אין cross-session messaging. מתחילים מ-`claude --version` ובודקים מול דרישות הגרסה בדף הרשמי.
- **הפקודה עובדת אבל הודעה לא הגיעה:** הפיצ'ר פעיל ומשהו צר יותר חוסם. למשל deny rule, ‏`crossSessionInbound` של הסשן המקבל, או סשן ענן שלא מופיע כי הסשן לא מחובר ל-Remote Control.

בסשן עם הפיצ'ר, `/status` מציג גם שורת `Peer address` עם כתובת תיבת הדואר של הסשן, או `unavailable` והסיבה.

## מה המגבלות?
- **טקסט בלבד.** הודעות מובנות של agent team נשארות בתוך הצוות.
- **גודל מוגבל.** הודעה לסשן באותה מכונה נדחית מעל בערך מיליון תווים.
- **פרץ הודעות נחסם.** אחרי פרץ מהיר לאותו סשן, השליחות הבאות נדחות, ו-Claude מתבקש לאחד אותן להודעה אחת או לחכות.
- **לולאות נעצרות לבד.** הסשן המקבל מגביל קצב לכל שולח, זורק חזרות זהות ומחזיק בתור עד 50 הודעות.
