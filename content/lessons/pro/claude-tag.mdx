Claude Tag הוא אינטגרציה ל-Slack שמריצה את `@Claude` בערוצי הצוות כזהות משותפת של הארגון, עם גישה שמנהל מגדיר. כל מי שבערוץ מתייג את `@Claude` בשרשור ומעביר לו משימה. הוא זמין בתוכניות Team ו-Enterprise. ב-Pro וב-Max משתמשים בגרסה הקודמת, Claude Code in Slack.

## למה זה חשוב
הרבה עבודה מתחילה בשיחה ב-Slack: דיווח על באג, החלטה בשרשור, שאלה על סטטוס. עם Claude Tag לא צריך להעתיק את ההקשר לכלי אחר. מתייגים את Claude בשרשור, הוא עובד בסביבה מבודדת בענן, ומחזיר את התוצאה לאותו שרשור, כולל draft PR כשמדובר בקוד. כל הערוץ רואה את העבודה ויכול לכוון אותה.

<Callout type="note">
דף Claude Tag ב-code.claude.com מפנה ל-[תיעוד Claude Tag ב-claude.com](https://claude.com/docs/claude-tag/overview) להגדרה ולשימוש. התיעוד שם מציין ש-Claude Tag נמצא ב-public beta, ושפיצ'רים והתנהגויות עשויים להשתנות לפני זמינות כללית.
</Callout>

## במה Claude Tag שונה מ-Claude Code in Slack?
יש שתי אינטגרציות, וההבדל העיקרי הוא בשם מי Claude עובד. לפי [דף Claude Code in Slack](https://code.claude.com/docs/en/slack), Anthropic מוציאה את הגרסה הקודמת משימוש ב-Team וב-Enterprise לטובת Claude Tag. האפליקציה הקיימת ב-Slack וה-handle ‏`@Claude` נשארים.

| | Claude Tag | Claude Code in Slack (הגרסה הקודמת) |
| --- | --- | --- |
| **תוכניות** | Team ו-Enterprise | Pro ו-Max (ב-Team וב-Enterprise יוצאת משימוש) |
| **בשם מי Claude עובד** | זהות משותפת של הארגון | החשבון האישי של כל משתמש |
| **מי קובע את הגישה** | מנהל, לכל ערוץ | החיבורים האישיים של המשתמש |
| **חיוב** | עבודה בערוצים מחויבת ליתרת השימוש של הארגון | מגבלות התוכנית של המשתמש |
| **DMs** | נתמכים, ורצים על החשבון האישי | לא נתמכים, רק ערוצים |

## איך מגדירים Claude Tag לסביבת עבודה?
Owner בארגון Claude מגדיר את Claude Tag פעם אחת, בדף [`claude.ai/admin-settings/claude-tag`](https://claude.ai/admin-settings/claude-tag). לפי [מדריך ההגדרה](https://claude.com/docs/claude-tag/admins/setup-overview), צריך מראש:

- תוכנית Team או Enterprise בשירות של Anthropic עצמה, לא דרך ספקי צד שלישי.
- תפקיד **Owner** בארגון Claude שמגדירים.
- מנהל של סביבת העבודה ב-Slack, כי רק הוא יכול לשלוח `@Claude connect`.
- **Routines** מופעלות לארגון. בלעדיהן Claude עונה שהוא לא זמין ולא עושה עבודה.
- ב-Team: קרדיטים ביתרת השימוש של הארגון.

Claude Tag לא זמין לארגונים עם Zero Data Retention או עם customer-managed encryption.

<StepList>

1. בדף ההגדרה לוחצים **Start setup**, ואז **Add the Claude app** ו-**Add to Slack** כדי להתקין את אפליקציית Claude ב-Slack.
2. ב-Slack פותחים ערוץ ומזמינים את Claude עם `/invite @Claude`.
3. מנהל סביבת העבודה שולח `@Claude connect` כהודעה חדשה בלי טקסט נוסף. Claude עונה בהודעה שרק הוא רואה, עם קוד צימוד שעובד פעם אחת ופג אחרי 15 דקות.
4. מדביקים את הקוד בדף ההגדרה ובוחרים **Entire workspace (recommended)** או **Specific channel**.
5. בוחרים לפחות שני כלים שהצוות עובד איתם. הבחירה עדיין לא מחברת אותם.
6. מחברים GitHub דרך ה-Claude GitHub App ובוחרים לאילו ריפוזיטוריז Claude יגיע.
7. יוצרים ל-Claude חשבון בכל כלי שבחרתם, ומדביקים בדף ההגדרה את מפתח ה-API שנוצר בחשבון הזה.
8. קובעים מגבלת הוצאה חודשית ומפעילים (launch). עד שלב זה Claude לא עונה לתיוגים.

</StepList>

אחרי ההפעלה, כל מי שנמצא בערוץ ש-Claude בו יכול להשתמש בו מיד, בלי הגדרה אישית.

### מה הפקודה /install-slack-app עושה?
`/install-slack-app` היא פקודה בתוך Claude Code. לפי [רשימת הפקודות](https://code.claude.com/docs/en/commands), היא מתקינה את אפליקציית Claude ל-Slack ופותחת דפדפן כדי להשלים את תהליך ה-OAuth:

<CommandBlock>/install-slack-app</CommandBlock>

התיעוד הרשמי לא מפרט את הקשר בין הפקודה לבין מדריך ההגדרה של Claude Tag. גם אחרי שהאפליקציה מותקנת, מדריך ההגדרה דורש את שלבי הצימוד וההפעלה בדף הניהול.

## איך מתייגים את Claude בערוץ?
Claude עובד רק בערוצים שהוזמן אליהם. מריצים את הפקודה בתיבת ההודעה של הערוץ, לא מתוך שרשור, כי Slack דוחה את `/invite` מתוך שרשור:

<CommandBlock>/invite @Claude</CommandBlock>

אחר כך כותבים `@Claude` ואת המשימה באותה הודעה. לפי [מדריך התחלת העבודה](https://claude.com/docs/claude-tag/users/getting-started), הדרך המהירה לבדוק שהוא עובד היא לשאול מה הוא יכול לראות מהערוץ:

```text
@Claude what can you access from this channel?
```

מה קורה אחרי התיוג:

- **התחלה:** שורת "is thinking…" בתחתית השרשור מסמנת ש-Claude קלט את ההודעה.
- **התקדמות:** משימה ארוכה מקבלת checklist ש-Claude מעדכן במקום. Slack לא שולח התראה על עריכת הודעה, כך ששרשור שקט בדרך כלל אומר שהעבודה נמשכת.
- **כיוון:** כל מי שבערוץ יכול להגיב בשרשור ולכוון את העבודה, בלי לתייג שוב. עריכה של הודעה קודמת מגיעה ל-Claude רק כהערה, ולכן תיקון כותבים בתגובה חדשה.
- **תוצאה:** תשובה, קובץ, גרף או draft PR, בתוך השרשור.

תיוג מבטיח תשובה. Claude עשוי לענות גם בלי תיוג כשהוא מעריך שיש צורך, ואחרי שתויג בשרשור הוא עוקב אחרי שאר התגובות בו.

## מתי לתייג בערוץ ומתי לשלוח DM?
המקום שבו כותבים ל-Claude קובע של מי הכלים שהוא משתמש בהם ומי רואה את התוצאה. זו ההשוואה מ-[איך Claude Tag עובד](https://claude.com/docs/claude-tag/concepts/how-it-works):

| עובדים ב… | גישה | שיוך העבודה | מתאים ל |
| --- | --- | --- | --- |
| ערוץ | החיבורים של הערוץ, שמנהל הגדיר | החשבונות של Claude עצמו | עבודה משותפת שהצוות צריך לראות |
| DM | הקונקטורים האישיים שלך ב-claude.ai | אתה | משימות אישיות עם המידע שלך |

ב-DM כל הודעה מגיעה ל-Claude בלי תיוג. DMs הם אחד-על-אחד בלבד, ו-group DMs לא נתמכים. DM לא צורך מיתרת השימוש של הארגון, אלא ממגבלות השימוש של המושב שלך.

## איך משימות מגיעות לסשני Claude Code?
ב-Claude Tag משימה שדורשת עבודה מקבלת סשן משלה בשרשור, שרץ ב-sandbox זמני בענן ולא על המחשב שלך. לפי התיעוד, ה-sandbox מריץ את אותו מנוע שמפעיל את [Claude Code בענן](/pro/web). Claude משכפל את הריפוזיטוריז אליו, עורך שם, ודוחף את השינויים ל-GitHub כ-branch או כ-PR. בעבודת קוד התוצאה היא בדרך כלל draft PR שנפתח תחת ה-Claude GitHub App, עם קישור בשרשור.

כמה דברים שכדאי לדעת:

- **כל שרשור נפרד:** שני שרשורים באותו ערוץ הם שני סשנים עם שני sandboxes נפרדים.
- **קבצים זמניים:** כמה דקות אחרי שהסשן מסיים תור, ה-sandbox משתחרר. השיחה נשמרת, אבל קבצים שהיו רק ב-sandbox לא. במשימה ארוכה מבקשים מ-Claude לדחוף branches תוך כדי עבודה.
- **סשן תקוע:** שולחים `@Claude !restart` כדי להתחיל סשן חדש שקורא מחדש את השרשור.
- **סביבת ענן:** לפי [דף Claude Code in Slack](https://code.claude.com/docs/en/slack), סשנים בערוץ של Claude Tag לא יכולים לרוץ בסביבת ענן אישית. Owner צריך לשתף את הסביבה עם הארגון או ליצור סביבה משותפת לארגון.

### ואיך זה עובד בגרסה הקודמת?
ב-Claude Code in Slack, שעדיין משמשת ב-Pro וב-Max, Claude מזהה אם ההודעה היא משימת קוד ויוצר סשן Claude Code בענן ב-claude.ai/code. ב-App Home של Claude ב-Slack בוחרים **Routing Mode**:

| מצב | התנהגות |
| --- | --- |
| **Code only** | כל תיוג עובר לסשן Claude Code |
| **Code + Chat** | Claude מנתח כל הודעה ומנתב ל-Claude Code למשימות קוד, או ל-Claude Chat לכל השאר |

אם הודעה נותבה לצ'אט אבל רצית סשן קוד, לוחצים **Retry as Code**. בסיום Claude מתייג אותך עם סיכום וכפתורים: **View Session** לפתיחת הסשן המלא ו-**Create PR** לפתיחת pull request. הגרסה הזו עובדת רק בערוצים, לא ב-DMs, ורק עם ריפוזיטוריז ב-GitHub.

## אילו הרשאות ובקרות ניהול יש?
ב-Claude Tag הגישה נקבעת לפי ערוץ, לא לפי אדם. Owner מצמיד **Access bundle**, אוסף חיבורים לשירותים חיצוניים, ל-scope: ערוץ, סביבת עבודה או כל הארגון. כך כל מי שבאותו ערוץ עובד עם אותה גישה. רוב הבקרות, לפי [דף הגבלת הגישה](https://claude.com/docs/claude-tag/admins/restrict-access), דורשות תפקיד Owner:

| בקרה | מה היא עושה |
| --- | --- |
| **Member access** | כברירת מחדל כל מי שבסביבת העבודה יכול להשתמש ב-Claude. ב-Team מגבילים לחברי הארגון, וב-Enterprise לתפקידים עם הרשאת **Claude Tag in Slack** |
| **Allow direct messages** | מפעיל או מכבה DMs לכל הארגון. ברירת המחדל: מופעל |
| ערוצים עם אורחים | ברירת המחדל **Restrict**: Claude לא עונה בערוץ שיש בו guest |
| גרסת Claude Tag לכל scope | **Off** משתיק את Claude ב-scope גם אם מזמינים אותו מחדש. ב-Team יש במקומה מתג **Enable Claude Tag** אחד לכל סביבות העבודה |
| **Channel manager** | ב-Enterprise בלבד: Owner מאציל ניהול של ערוץ מסוים, כמו מודל ברירת מחדל וריפוזיטוריז |
| מגבלת הוצאה | תקרה חודשית לשימוש של Claude Tag מיתרת הארגון |

כדי להוציא את Claude מערוץ, כל חבר בערוץ יכול להריץ `/remove @Claude`, אלא אם מנהל Slack הגביל זאת. כדי לבדוק מה Claude יכול לראות בערוץ מסוים, פשוט שואלים אותו. אם הוא לא מגיע למשהו, הערוץ לא קיבל גישה אליו.

בגרסה הקודמת הבקרה פשוטה יותר: מנהלי Slack מחליטים אם להתקין את האפליקציה, הסרה שלה מבטלת מיד את הגישה לכל המשתמשים, והגישה בפועל נקבעת לפי הערוצים ש-Claude הוזמן אליהם.

<Callout type="warning">
כשמתייגים את Claude, הוא מקבל את הקשר השיחה ועלול לפעול לפי הוראות שמופיעות בהודעות אחרות בשרשור. [דף Claude Code in Slack](https://code.claude.com/docs/en/slack) ממליץ להשתמש ב-Claude רק בשיחות Slack מהימנות. לפי התיעוד של Claude Tag, מחיקה או עריכה של הודעה ב-Slack לא מסירה אותה מהתמליל של הסשן.
</Callout>
