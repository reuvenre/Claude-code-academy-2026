Ultrareview היא ביקורת קוד עמוקה של Claude Code שרצה כסשן ענן בתשתית של Anthropic. מריצים `/code-review ultra`, וצי של סוכני ביקורת מחפש באגים ב-branch או ב-PR, ומאמת כל ממצא באופן עצמאי. היא לוקחת בערך 5 עד 10 דקות, ומתאימה לפני merge של שינוי משמעותי.

## איך הופכים ביקורת קוד להרגל יומיומי?
הקורס [Claude Code 101 ב-Claude Academy](https://academy.claude.com/courses/claude-code-101/code-review) ממליץ לא להסתפק בסיכום ש-Claude כותב בסוף משימה, ולעבור על כל שינוי לפני שמשאירים אותו:

1. **קוראים את ה-diff.** `/diff` פותח תצוגה אינטראקטיבית של השינויים שעוד לא נכנסו ל-commit. מחפשים שינויים שלא ביקשת, בדיקות שנמחקו או הוחלשו, ותלויות חדשות או ערכים קשיחים כמו URL או מפתח בתוך הקוד.
2. **מבקשים דעה שנייה מהקשר נקי.** הסשן שכתב את הקוד סוחב איתו את כל ההיסטוריה שלו, ולכן הוא לא השופט הכי טוב של העבודה של עצמו. `/code-review` בודק את השינוי בלי ההיסטוריה של הסשן, ולא עורך כלום אלא אם ביקשת.
3. **ממיינים כל ממצא לאחת משלוש קבוצות:** לתקן עכשיו, כשזו בעיה אמיתית שחשובה. לשאול למה, כשהממצא נראה מפוקפק: מצטטים אותו בחזרה ומבקשים מ-Claude לבדוק שוב. או להשאיר, כשהבעיה אמיתית אבל קטנה, ואפשר לאסוף אותה לסבב תיקונים עתידי. כשמבקשים תיקון, מבקשים גם הוכחה, למשל להריץ את הבדיקות ולהציג את הפלט.

## למה זה חשוב
ביקורת מקומית מהירה טובה תוך כדי עבודה, אבל היא יכולה לפספס בעיות. לפי התיעוד הרשמי, ultrareview מוסיפה שלושה דברים:

- **אות גבוה יותר:** כל ממצא משוחזר ומאומת באופן עצמאי, כך שהתוצאות מתמקדות בבאגים אמיתיים ולא בהערות סגנון.
- **כיסוי רחב יותר:** צי גדול יותר של סוכנים בודק את השינוי במקביל.
- **בלי משאבים מקומיים:** הכל רץ ב-sandbox בענן, והטרמינל שלך פנוי לעבודה אחרת.

<Callout type="note">
Ultrareview נמצאת ב-research preview. הפיצ'ר, התמחור והזמינות עשויים להשתנות. הפקודה היא `/code-review ultra`, וכש-ultrareview זמינה לחשבון שלך, גם `/ultrareview` עובד ככינוי.
</Callout>

## איך עובד /code-review הרגיל?
`/code-review` בודק diff בטרמינל ומדווח על באגי נכונות (correctness) ועל הזדמנויות לשימוש חוזר, פישוט ויעילות. `/review` הוא כינוי שלו. בלי ארגומנטים, הוא בודק את ה-commits של ה-branch מעבר ל-upstream שלו, יחד עם שינויים שלא נכנסו ל-commit:

<CommandBlock>/code-review</CommandBlock>

אפשר להעביר יעד אחר: נתיב קובץ, מספר PR, שם branch או טווח כמו `main...my-feature`. הביקורת רצה ברקע כ-subagent עם חלון הקשר משלו, והממצאים מגיעים לשיחה כשהיא מסתיימת. ההסבר המלא נמצא ב[דף Code Review](https://code.claude.com/docs/en/code-review#review-a-diff-locally).

### מה עושות רמות ה-effort?
מעבירים [רמת effort](https://code.claude.com/docs/en/model-config#adjust-effort-level) כדי לבחור בין ביטחון לכיסוי:

| רמה | מה מקבלים |
| --- | --- |
| `low`, ‏`medium` | רק הממצאים שהביקורת הכי בטוחה בהם, פחות false positives |
| `high` עד `max` | כיסוי רחב יותר, כולל ממצאים שהביקורת פחות בטוחה בהם |
| `ultra` | ultrareview בענן, צי סוכנים עם אימות עצמאי |

למשל `/code-review high`. כשלא מקלידים רמה, הביקורת חוזרת על הרמה האחרונה שהקלדת מ-`low` עד `max`, גם מסשן קודם. `ultra` לא משתמש ברמה השמורה ולא מעדכן אותה.

### אילו דגלים יש?
- `--fix`: מחיל את הממצאים על עץ העבודה אחרי הביקורת.
- `--comment`: מפרסם את הממצאים כהערות inline ב-PR של GitHub, או כהערה אחת ב-merge request של GitLab.
- `--post`: רק בביקורת `ultra` על PR ב-`github.com`. מסמן מראש את אפשרות הפרסום בדיאלוג ההפעלה.

<Callout type="warning">
ביקורת ברקע מחילה את עריכות `--fix` מחוץ ל-checkpoints של הסשן, ולכן `/rewind` לא מבטל אותן. כדי לבטל, משתמשים ב-git.
</Callout>

## איך מריצים ultrareview על branch?
מתוך ריפו git מריצים:

<CommandBlock>/code-review ultra</CommandBlock>

בלי ארגומנטים, ultrareview בודקת את ה-diff בין ה-branch הנוכחי ל-branch ברירת המחדל, כולל שינויים שלא נכנסו ל-commit ושינויים ב-staging. Claude Code אורז את מצב הריפו ומעלה אותו ל-sandbox בענן.

<StepList>

1. מריצים `/code-review ultra`.
2. בודקים את דיאלוג האישור: היקף הביקורת (כולל מספר הקבצים והשורות), הריצות החינמיות שנותרו והעלות המשוערת.
3. מאשרים. הביקורת ממשיכה ברקע, ואפשר להמשיך לעבוד בסשן.
4. כשהיא מסתיימת, הממצאים המאומתים מגיעים כהתראה בסשן. לכל ממצא יש מיקום בקובץ והסבר, ואפשר לבקש מ-Claude לתקן אותו.

</StepList>

Claude לא מפעיל ultrareview מיוזמתו. היא רצה רק כשאתה מקליד `/code-review ultra`.

### איך משווים מול base אחר?
מעבירים שם branch. הדוגמה מהתיעוד בודקת את ה-branch הנוכחי מול `develop`:

<CommandBlock>/code-review ultra develop</CommandBlock>

ה-branch לא חייב להיות קיים ב-clone המקומי, כי Claude Code מושך אותו מ-`origin`. אפשר להעביר גם commit id או tag כ-base.

### אפשר להוסיף הערה במילים?
כן. טקסט של יותר ממילה אחת, שאינו שם branch או הפניה ל-PR, נשמר כהערה לביקורת:

```text
/code-review ultra check my auth changes
```

הביקורת עדיין מכסה את ה-branch הנוכחי, ו-Claude מקשר את הממצאים להערה. מילה אחת נקראת תמיד כשם branch או כהפניה ל-PR.

## איך מריצים ultrareview על pull request?
מעבירים את מספר ה-PR:

<CommandBlock>/code-review ultra 1234</CommandBlock>

הפקודה מקבלת גם `#1234`, ‏`PR 1234` וכתובת PR מודבקת, בתנאי שהיא מצביעה על הריפו שבתיקייה הנוכחית. במצב PR, ה-sandbox משכפל את ה-PR ישירות מהשרת, ו-Claude Code לא מעלה שום דבר מהמחשב שלך.

- זה עובד עם ריפו ב-`github.com`, ועם GitHub Enterprise Server שמחובר ל-Claude Code.
- ב-`github.com`, השכפול נעשה עם חשבון GitHub שמחובר לחשבון Claude שלך, והוא צריך הרשאת קריאה לריפו. `/web-setup` מחבר את ההתחברות של GitHub CLI (`gh`) לחשבון Claude שלך.

<Callout type="tip">
אם הריפו גדול מדי לאריזה, Claude Code מציע לעבור למצב PR. דוחפים את ה-branch, פותחים draft PR ומריצים `/code-review ultra <PR-number>`.
</Callout>

### איך מפרסמים את הממצאים ב-PR?
ב-PR על `github.com` אפשר לבקש מ-Claude לפרסם את הממצאים כתגובה רגילה אחת מחשבון GitHub שלך. התגובה היא לא review ולא approval. ברירת המחדל היא לא לפרסם, ובוחרים מחדש בכל ריצה:

- **בסשן אינטראקטיבי:** בוחרים בדיאלוג ההפעלה את **Run and post the findings to the PR as me**. הדגל `--post` רק מסמן את הבחירה מראש, ו-Claude Code עדיין שואל.
- **בלי סשן:** מריצים `claude ultrareview` עם `--post`.

בסשן אינטראקטיבי משאירים את הסשן פתוח עד שהביקורת מסתיימת. אם הסשן נסגר קודם, שום דבר לא מתפרסם.

## כמה זה עולה ומה המגבלות?
Ultrareview מחויבת כ-usage credits, ולא מהשימוש הכלול בתוכנית:

| תוכנית | ריצות חינם | אחרי הריצות החינמיות |
| --- | --- | --- |
| Pro | 3 | usage credits |
| Max | 3 | usage credits |
| Team ו-Enterprise | אין | usage credits |

- הריצות החינמיות הן הקצאה חד-פעמית לחשבון, והן לא מתחדשות.
- ביקורת בתשלום עולה בדרך כלל 5 עד 25 דולר, לפי גודל השינוי. זו גם ההערכה שדיאלוג ההפעלה מציג.
- ריצה נספרת מרגע שסשן הענן מתחיל. ביקורת שעצרת או שנכשלה עדיין צורכת ריצה חינמית, וביקורת בתשלום מחויבת רק על מה שרץ.
- כדי להפעיל ביקורת בתשלום, usage credits צריכים להיות מופעלים בחשבון או בארגון. בודקים ומשנים את ההגדרה עם `/usage-credits`.

ב-branch יש גם מגבלת גודל: כברירת מחדל עד 500 קבצים שהשתנו ו-8,000 שורות שהשתנו. הערכים עשויים להשתנות, והודעת הסירוב מציינת את הערכים בתוקף ואת גודל ה-diff שלך. כשה-diff ריק, ultrareview מסרבת ומציעה מה לעשות, למשל לעבור ל-branch עם העבודה שלך או להעביר base אחר.

<Callout type="warning">
Ultrareview דורשת התחברות עם חשבון claude.ai. היא לא זמינה עם API key בלבד, עם Amazon Bedrock,‏ Google Cloud's Agent Platform או Microsoft Foundry, ולא בארגונים עם Zero Data Retention. במקרים האלה `/code-review ultra` מריץ ביקורת מקומית בסשן. עם API key מריצים `/login` ומתחברים עם claude.ai.
</Callout>

## איך עוקבים אחרי ביקורת שרצה?
מריצים `/tasks`. שם רואים ביקורות שרצות ושהסתיימו, פותחים תצוגת פרטים או עוצרים ביקורת. ביקורת שנעצרה לא מחזירה ממצאים חלקיים. אפשר גם לסגור את הטרמינל, כי הביקורת רצה בענן, אלא אם בחרת לפרסם את הממצאים ב-PR.

## איך מריצים ultrareview מסקריפט או מ-CI?
משתמשים בתת-הפקודה `claude ultrareview`. היא מפעילה את אותה ביקורת, מחכה עד שהיא מסתיימת ומדפיסה את הממצאים ל-stdout:

```bash
claude ultrareview
claude ultrareview 1234
claude ultrareview origin/main
```

| דגל | מה הוא עושה |
| --- | --- |
| `--json` | מדפיס את ה-payload הגולמי של `bugs.json` במקום ממצאים מעוצבים |
| `--timeout <minutes>` | זמן ההמתנה המקסימלי בדקות. ברירת המחדל: 45 |
| `--post` | מפרסם את הממצאים כתגובה אחת ב-PR ב-`github.com` |
| `--no-post` | לא מפרסם. זו ברירת המחדל |

קודי יציאה: `0` כשהביקורת הסתיימה (עם ממצאים או בלי), `1` כשההפעלה נכשלה, הביקורת נעצרה, סשן הענן נכשל או שעבר ה-timeout, ו-`130` כשעצרת עם Ctrl-C. הודעות התקדמות וכתובת הסשן יוצאות ל-stderr, כך ש-stdout נשאר נקי לעיבוד.

הרצה של `claude ultrareview` בעצמך נחשבת להסכמה לחיוב. לעומת זאת, `claude -p '/code-review ultra'` רק מפעיל את הביקורת ומדפיס קישור מעקב, ועוצר לפני ההפעלה אם הביקורת תחויב ב-usage credits.

<Callout type="tip">
לביקורת אוטומטית על כל PR ב-GitHub, בלי שלב CLI, יש את השירות המנוהל [Code Review](https://code.claude.com/docs/en/code-review), שמפרסם ממצאים כהערות inline. הוא זמין בתוכניות Team ו-Enterprise.
</Callout>

## מתי להשתמש בכל אחת?

|  | `/code-review` | `/code-review ultra` |
| --- | --- | --- |
| איפה רץ | מקומית בסשן | ב-sandbox בענן |
| עומק | לפי רמת ה-effort | צי סוכנים עם אימות עצמאי |
| משך | שניות עד כמה דקות | בערך 5 עד 10 דקות |
| עלות | נספר בשימוש הרגיל | ריצות חינם, ואז בערך 5 עד 25 דולר ב-usage credits |
| מתאים ל | משוב מהיר תוך כדי עבודה | ביטחון לפני merge של שינוי משמעותי |

ההמלצה מהתיעוד: `/code-review` למשוב מהיר, או עם מספר PR כדי לבדוק PR של חבר צוות לפני אישור. `/code-review ultra` לפני merge של שינוי משמעותי, כשרוצים מעבר עמוק שתופס מה שביקורת מקומית עלולה לפספס.
