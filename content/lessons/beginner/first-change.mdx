import { CommandBlock, Callout, StepList } from "@/components/lesson";

מבקשים את השינוי במילים, למשל `add a hello world function to the main file`. Claude Code מוצא את הקובץ המתאים ומציג את העריכה. אם הוא מבקש אישור, בוחרים **Yes**. אחר כך בודקים את השינוי עם `/diff`, ואם משהו לא טוב, לוחצים `Esc` פעמיים כדי לחזור אחורה.

## למה זה חשוב
זה הרגע שבו Claude Code עובר משאלות לעשייה. כדאי להתחיל בשינוי קטן, כדי לראות איך הוא בוחר קבצים, איך נראה אישור, ואיך בודקים ומבטלים. ככה תדע שאפשר לנסות דברים בלי פחד.

## איך מבקשים שינוי?

<StepList>

1. פותחים סשן בתיקיית הפרויקט:
   <CommandBlock>claude</CommandBlock>
2. כותבים בקשה פשוטה. זו הדוגמה מהמדריך הרשמי:
   ```text
   add a hello world function to the main file
   ```
3. Claude Code מוצא את הקובץ המתאים ומציג את השינוי. לא צריך להגיד לו איזה קובץ לפתוח.
4. אם הוא מבקש אישור לפני השינוי, בוחרים **Yes**.

</StepList>

## למה לפעמים הוא לא שואל?
זה תלוי במצב ההרשאות (permission mode), שקובע מה Claude רשאי לעשות בלי לשאול:

- **Manual:** Claude שואל לפני עריכת קבצים ולפני פקודות shell. זה מצב ההתחלה המובנה בתוכניות שאינן Pro,‏ Max או Team.
- **Auto:** מסווג (classifier) בודק את הפעולות ברקע וחוסם את המסוכנות, ו-Claude עורך את רוב הקבצים ומריץ את רוב הפקודות בלי לשאול. זה מצב ההתחלה המובנה בסשנים אינטראקטיביים בטרמינל בתוכניות Pro,‏ Max ו-Team.

ההגדרות שלך או של הארגון יכולות לקבוע מצב התחלה אחר. לוחצים `Shift+Tab` בכל רגע כדי להחליף מצב בסשן הנוכחי. ברמה 1 יש שיעור שלם על מצבי ההרשאות.

## איך בודקים מה השתנה?
מקלידים בתוך הסשן:

<CommandBlock>/diff</CommandBlock>

הפקודה מציגה את השינויים בתיקיית העבודה, כולל כל העריכות ש-Claude עשה עד עכשיו. כדאי להסתכל על השינוי לפני שממשיכים הלאה.

## איך מבטלים עריכה?
לפני כל עריכה Claude שומר תמונת מצב של הקובץ (checkpoint). יש שלוש דרכים לחזור אחורה:

- לוחצים `Esc` פעמיים.
- מקלידים `/rewind` ובוחרים נקודה קודמת בשיחה או בקוד.
- פשוט מבקשים מ-Claude לבטל את השינוי.

<Callout type="warning">
checkpoints מחזירים רק קבצים. פעולות שמשפיעות על מערכות חיצוניות, כמו מסדי נתונים, APIs ופריסות, אי אפשר להחזיר אחורה.
</Callout>

## מה עושים כשהתוצאה לא מדויקת?
ממשיכים את השיחה. Claude Code עובד בשיחה, ולא צריך פרומפט מושלם. זו הדוגמה מהתיעוד הרשמי: מתחילים בבקשה כללית,

```text
Fix the login bug
```

ואם Claude הלך לכיוון הלא נכון, מתקנים אותו:

```text
That's not quite right. The issue is in the session handling.
```

Claude משנה גישה וממשיך מאותה נקודה. אפשר גם לכתוב תיקון בזמן שהוא עובד וללחוץ `Enter`: ההודעה נכנסת לתור, והוא מתאים את הצעד הבא.

## דוגמאות לשינויים הבאים
כשהשינוי הראשון עבד, אפשר לעבור למשימות אמיתיות. אלה דוגמאות מהמדריך הרשמי:

```text
add input validation to the user registration form
```

```text
write unit tests for the calculator functions
```

```text
update the README with installation instructions
```
