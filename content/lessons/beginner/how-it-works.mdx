Claude Code עובד בלולאה אג׳נטית של שלושה שלבים: איסוף הקשר, ביצוע פעולה ובדיקת התוצאה, וחוזר עליהם עד שהמשימה גמורה. המודל מחליט מה לעשות, והכלים מבצעים: קריאה ועריכה של קבצים, חיפוש והרצת פקודות. אתה יכול לעצור ולכוון אותו בכל רגע.

## למה זה חשוב
כשמבינים איך Claude Code חושב, יודעים מה לבקש ממנו ומתי להתערב. הוא לא מחכה שתגיד לו אילו קבצים לפתוח. הוא מחליט לבד, לומד מכל צעד, ומתקן את הכיוון תוך כדי עבודה.

## מהי הלולאה האג׳נטית?
כשנותנים ל-Claude משימה, הוא עובר בין שלושה שלבים שמשתלבים זה בזה:

1. **איסוף הקשר:** מחפש וקורא קבצים כדי להבין את הקוד.
2. **ביצוע פעולה:** עורך קבצים או מריץ פקודות.
3. **בדיקת התוצאה:** למשל מריץ בדיקות כדי לוודא שהשינוי עובד.

הלולאה מתאימה את עצמה למשימה. שאלה על הקוד אולי דורשת רק איסוף הקשר. תיקון באג עובר בכל השלבים שוב ושוב. Claude מחליט מה כל צעד צריך לפי מה שלמד בצעד הקודם, ויכול לשרשר עשרות פעולות.

גם אתה חלק מהלולאה: אפשר לעצור בכל נקודה, להוסיף הקשר או לבקש גישה אחרת.

## מה עושה המודל ומה עושים הכלים?
הלולאה נשענת על שני רכיבים:

- **המודל** חושב: קורא קוד בכל שפה, מבין איך החלקים מתחברים ומחליט מה לשנות. יש כמה מודלים עם יתרונות שונים. מחליפים מודל עם `/model` בתוך הסשן, והרשימה העדכנית נמצאת ב[דף בחירת המודל בתיעוד הרשמי](https://code.claude.com/docs/en/model-config).
- **הכלים** פועלים. בלעדיהם Claude יכול רק לענות בטקסט. איתם הוא יכול לקרוא קוד, לערוך קבצים ולהריץ פקודות.

Claude Code עצמו הוא השכבה שעוטפת את המודל: הוא מספק את הכלים ומנהל את ההקשר שהמודל רואה. לשכבה הזו קוראים agentic harness.

הכלים המובנים מתחלקים לחמש קטגוריות:

| קטגוריה | מה Claude יכול לעשות |
| --- | --- |
| פעולות על קבצים | לקרוא, לערוך, ליצור ולשנות שם |
| חיפוש | למצוא קבצים לפי תבנית ולחפש בתוכן עם regex |
| הרצה | להריץ פקודות shell, להפעיל שרתים, להריץ בדיקות ולהשתמש ב-git |
| רשת | לחפש ברשת, לקרוא תיעוד ולחפש הודעות שגיאה |
| הבנת קוד | לראות שגיאות טיפוסים אחרי עריכה ולקפוץ להגדרות (דורש plugins ייעודיים) |

## דוגמה: "תתקן את הבדיקות שנכשלות"
כשמבקשים "fix the failing tests", Claude עשוי לעבוד כך:

<StepList>

1. מריץ את הבדיקות כדי לראות מה נכשל.
2. קורא את פלט השגיאה.
3. מחפש את קובצי המקור הרלוונטיים.
4. קורא אותם כדי להבין את הקוד.
5. עורך אותם כדי לתקן.
6. מריץ שוב את הבדיקות כדי לוודא שהתיקון עובד.

</StepList>

כל שימוש בכלי נותן לו מידע חדש שקובע את הצעד הבא. זו הלולאה האג׳נטית בפעולה.

## מה Claude Code רואה בפרויקט שלך?
כשמריצים את הפקודה הבאה בתיקייה:

<CommandBlock>claude</CommandBlock>

Claude Code מקבל גישה ל:

- **הפרויקט:** הקבצים בתיקייה ובתתי-התיקיות, וקבצים במקומות אחרים באישורך.
- **הטרמינל:** כל פקודה שאתה יכול להריץ, כמו כלי build,‏ git ומנהלי חבילות.
- **מצב ה-git:** ה-branch הנוכחי, שינויים שעוד לא נשמרו ב-commit, והיסטוריית commits אחרונה.
- **CLAUDE.md:** קובץ הנחיות לפרויקט שנטען בכל סשן.
- **auto memory:** לקחים ש-Claude שומר לבד תוך כדי עבודה.
- **הרחבות שהגדרת:** שרתי MCP,‏ skills ו-subagents.

כל סשן חדש מתחיל עם חלון הקשר נקי, בלי השיחות הקודמות. מה שחשוב לזכור לאורך זמן שייך ל-CLAUDE.md.

## איך עוצרים, מכוונים ומבטלים?
Claude עובד לבד, אבל נשאר קשוב אליך:

- **`Esc`** עוצר אותו מיד. הפעולה שרצה מתבטלת, והוא מחכה להוראה הבאה.
- **כתיבת תיקון ו-`Enter`** בלי לעצור: ההודעה נכנסת לתור, ו-Claude קורא אותה ומתאים את הצעד הבא.
- **`Esc` פעמיים** מחזיר קבצים למצב קודם. לפני כל עריכה Claude שומר תמונת מצב של הקובץ (checkpoint).
- **`Shift+Tab`** מחליף מצב הרשאות, כלומר מה Claude רשאי לעשות בלי לשאול. נרחיב על המצבים ברמה 1.

<Callout type="warning">
checkpoints מכסים רק שינויים בקבצים. פעולות במערכות חיצוניות, כמו מסדי נתונים, APIs ופריסות, אי אפשר להחזיר אחורה. את אלה מגבילים דרך מצב ההרשאות וכללי ההרשאות.
</Callout>
