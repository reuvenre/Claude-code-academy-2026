CLAUDE.md למה ש-Claude צריך לדעת תמיד. Skill לידע ול-workflows שנטענים לפי דרישה. Subagent למשימה שצריכה הקשר מבודד. Hook לפעולה שחייבת לקרות בכל אירוע. MCP לחיבור שירותים חיצוניים. Plugin אורז את כל אלה ליחידה אחת שאפשר להתקין בריפו אחר או לשתף.

## למה זה חשוב
הכלים המובנים של Claude Code מכסים את רוב משימות הקוד. ההרחבות הן שכבה שמוסיפים מעליהם: מה Claude יודע, לאילו שירותים הוא מחובר, ומה קורה אוטומטית. כל הרחבה נטענת בנקודה אחרת וצורכת כמות אחרת של הקשר. בחירה לא נכונה עולה בהקשר מבוזבז, או בכלל שלא נאכף. ברמה הזו יש שיעור נפרד לכל אחת. כאן בונים את המפה.

## מה כל הרחבה עושה, ומתי בוחרים בה?
זו הטבלה המרכזית, לפי התיעוד הרשמי:

| הרחבה | מה היא עושה | מתי להשתמש | דוגמה מהתיעוד |
| --- | --- | --- | --- |
| **CLAUDE.md** | הקשר קבוע שנטען בכל שיחה | מוסכמות הפרויקט, כללי "תמיד לעשות X" | "Use pnpm, not npm. Run tests before committing." |
| **Skill** | הנחיות, ידע ו-workflows ש-Claude יכול להשתמש בהם | תוכן לשימוש חוזר, חומר עזר, משימות שחוזרות | `/deploy` מריץ את רשימת הבדיקות של הפריסה |
| **Subagent** | הקשר ריצה מבודד שמחזיר תוצאות מסוכמות | בידוד הקשר, משימות במקביל, עובדים מתמחים | מחקר שקורא הרבה קבצים ומחזיר רק את הממצאים |
| **Hook** | סקריפט, בקשת HTTP, קריאה לכלי MCP, prompt או Subagent שמופעלים מאירועים | אוטומציה שחייבת לרוץ בכל אירוע מתאים | הרצת ESLint אחרי כל עריכת קובץ |
| **MCP** | חיבור לשירותים חיצוניים | נתונים או פעולות מחוץ לפרויקט | שאילתה למסד הנתונים, הודעה ל-Slack, שליטה בדפדפן |
| **Plugin** | שכבת אריזה: Skills,‏ Hooks,‏ Subagents ושרתי MCP ביחידה אחת שמתקינים | אותה הגדרה בכמה ריפו, או הפצה לאחרים דרך marketplace | Skills של plugin מקבלים namespace, כמו `/my-plugin:review` |

לפי התיעוד, Skills הן ההרחבה הגמישה ביותר. Skill הוא קובץ Markdown עם ידע, workflow או הנחיות. מפעילים אותו בפקודה כמו `/deploy`, או ש-Claude טוען אותו לבד כשהוא רלוונטי.

<Callout type="note">
הטבלה בתיעוד כוללת עוד הרחבות: Output styles (טון ופורמט התשובה, [שיעור 28](/advanced/output-styles)), Code intelligence, Dynamic workflows,‏ Cross-session messaging ו-Artifacts. הרשימה המלאה ב[דף הרשמי](https://code.claude.com/docs/en/features-overview).
</Callout>

## מתי מוסיפים כל הרחבה?
לא צריך להגדיר הכול מראש. לכל הרחבה יש סימן מזהה, ולפי התיעוד רוב הצוותים מוסיפים אותן בערך בסדר הזה:

| הסימן | מה מוסיפים |
| --- | --- |
| Claude טועה פעמיים באותה מוסכמה או פקודה | שורה ב-CLAUDE.md |
| אתה מבקש שוב ושוב תשובות קצרות יותר, יותר הסברים או אותו פורמט | Output style |
| אתה מקליד שוב ושוב את אותו prompt כדי להתחיל משימה | Skill שמפעילים ידנית |
| אתה מדביק בפעם השלישית את אותו נוהל רב-שלבי | Skill |
| אתה מעתיק שוב ושוב נתונים מלשונית בדפדפן ש-Claude לא רואה | שרת MCP לאותה מערכת |
| Claude קורא הרבה קבצים כדי למצוא איפה symbol מוגדר או בשימוש | plugin של code intelligence לשפה שלך |
| משימת צד מציפה את השיחה בפלט שלא תחזור אליו | Subagent |
| אתה רוצה שמשהו יקרה בכל פעם בלי לבקש | Hook |
| ריפו שני צריך את אותה הגדרה | Plugin |

אותם סימנים אומרים גם מתי לעדכן את מה שכבר יש. טעות שחוזרת היא עריכה של CLAUDE.md, ולא תיקון חד-פעמי בצ'אט.

## איך מבדילים בין הרחבות שנראות דומות?

### CLAUDE.md או Skill?
שניהם מחזיקים הנחיות, אבל נטענים אחרת:

| | CLAUDE.md | Skill |
| --- | --- | --- |
| **נטען** | בכל סשן, אוטומטית | לפי דרישה |
| **מפעיל workflow** | לא | כן, עם `/<name>` |
| **מתאים ל** | כללי "תמיד לעשות X" | חומר עזר ו-workflows |

אם Claude צריך לדעת את זה תמיד (פקודות build, מבנה הפרויקט, "לעולם אל תעשה X"), זה ב-CLAUDE.md. אם זה חומר שנדרש לפעמים (תיעוד API, מדריך סגנון) או workflow כמו deploy או review, זה Skill. כלל אצבע מהתיעוד: פחות מ-200 שורות ב-CLAUDE.md. כשהוא גדל, מעבירים חומר עזר ל-Skills או מפצלים לקבצים ב-`.claude/rules/`.

### Skill או Subagent?
Skill הוא תוכן שנטען לתוך ההקשר הנוכחי ומוסיף לחלון הראשי. Subagent הוא עובד מבודד עם חלון הקשר משלו, ורק הסיכום חוזר לשיחה הראשית. בוחרים Subagent כשמשימה קוראת עשרות קבצים, כשרוצים עבודה במקביל, או כשחלון ההקשר מתמלא. השניים משתלבים: Subagent יכול לטעון Skills מראש, ו-Skill יכול לרוץ בהקשר מבודד.

### Hook או Skill?
Hook רץ תמיד באירוע שלו, כמו `PostToolUse` או `SessionStart`. Skill הוא הנחיות ש-Claude מפרש, והתוצאה יכולה להשתנות. בוחרים Hook כשהפעולה צריכה לקרות באותה דרך בכל פעם ולא דורשת חשיבה: פורמט אחרי שמירה, חסימת `rm -rf /`, הודעה ל-Slack בסוף סשן. בוחרים Skill כש-Claude צריך להחליט איך ליישם את הצעדים, כמו רשימת בדיקות ל-release או playbook לדיבאג.

<Callout type="warning">
הוראה כמו "never edit `.env`" ב-CLAUDE.md או ב-Skill היא בקשה, לא הבטחה. Hook מסוג `PreToolUse` שחוסם את העריכה הוא אכיפה. כלל שחייב להתקיים בכל פעם כותבים כ-Hook.
</Callout>

### MCP או Skill?
MCP נותן ל-Claude כלים ייעודיים למערכת חיצונית, והשרת מטפל בחיבור ובאימות. Skill נותן ל-Claude ידע איך להשתמש בכלים האלה נכון. למשל: MCP מתחבר למסד הנתונים, ו-Skill מתעד את הסכמה ואת דפוסי השאילתות של הצוות.

## כמה הקשר כל הרחבה צורכת?
כל הרחבה צורכת חלק מחלון ההקשר. יותר מדי הקשר גם מוסיף רעש: Skills עלולים לא להיטען נכון, ו-Claude עלול לאבד את המוסכמות שלך.

| הרחבה | מתי נטענת | מה נטען | עלות הקשר |
| --- | --- | --- | --- |
| **CLAUDE.md** | תחילת הסשן | כל התוכן | בכל בקשה |
| **Output styles** | תחילת הסשן, ושוב כשמחליפים סגנון | ההנחיות המלאות של הסגנון הפעיל; כלום בסגנון Default | בכל בקשה |
| **Skills** | תחילת הסשן + בשימוש | תיאורים בהתחלה, תוכן מלא בשימוש | נמוכה (התיאורים בכל בקשה) |
| **שרתי MCP** | תחילת הסשן | שמות הכלים; סכמות מלאות לפי דרישה | נמוכה עד שמשתמשים בכלי |
| **Subagents** | כשמפעילים אחד | הקשר חדש עם ה-Skills שהוגדרו לו, או השיחה עד כה במקרה של fork | מבודדת מהסשן הראשי |
| **Hooks** | באירוע | כלום, רצים מחוץ לשיחה | אפס, אלא אם ה-Hook מחזיר פלט |

<Callout type="tip">
ב-Skill עם תופעות לוואי מגדירים `disable-model-invocation: true` ב-frontmatter. כך רק אתה מפעיל אותו, והוא לא צורך הקשר עד שמפעילים אותו.
</Callout>

## איך ההרחבות משתלבות בהגדרה אמיתית?
כל הרחבה פותרת בעיה אחרת, והגדרות אמיתיות משלבות ביניהן. הדוגמה מהתיעוד: CLAUDE.md למוסכמות הפרויקט, Skill ל-workflow הפריסה, MCP לחיבור למסד הנתונים, ו-Hook שמריץ linting אחרי כל עריכה.

| שילוב | איך זה עובד |
| --- | --- |
| **Skill + MCP** | MCP נותן את החיבור, ה-Skill מלמד להשתמש בו נכון |
| **Skill + Subagent** | Skill בשם `/audit` מפעיל Subagents לאבטחה, ביצועים וסגנון, כל אחד בהקשר מבודד |
| **CLAUDE.md + Skills** | CLAUDE.md אומר "follow our API conventions", ו-Skill מכיל את מדריך ה-API המלא |
| **Hook + MCP** | Hook אחרי עריכה שולח הודעה ל-Slack כש-Claude משנה קבצים קריטיים |

כשאותה הרחבה מוגדרת בכמה רמות (משתמש, פרויקט, plugin), קובצי CLAUDE.md מצטרפים יחד, Hooks מכל המקורות רצים כולם, ו-Skills,‏ Subagents ושרתי MCP עם אותו שם דורסים זה את זה לפי סדר עדיפויות. את הפרטים תמצא בשיעור של כל הרחבה.
