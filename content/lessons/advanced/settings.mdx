Claude Code קורא הגדרות מקובצי JSON בשם `settings.json`. הקובץ שבו שומרים הגדרה קובע על מי היא חלה: רק עליך, על כל מי שעובד בפרויקט, או על כל הארגון. משנים הגדרות דרך `/config`, בעריכת הקובץ, או לסשן אחד משורת הפקודה.

## למה זה חשוב
הגדרות קובעות איך Claude Code מתנהג: באיזה מודל הוא מתחיל, מה מותר לו להריץ בלי לשאול, אילו קבצים אסור לו לקרוא, איך הוא נראה בטרמינל, ומה הארגון אוכף. אם שומרים הגדרה בקובץ הלא נכון, היא לא תגיע לצוות, או שתדרוס את ההעדפות של כולם. ההבנה של ה-scope וסדר העדיפויות חוסכת את רוב הבלבול סביב "למה ההגדרה שלי לא עובדת".

## איפה יושבים קובצי ההגדרות?
יש ארבעה סוגים של קבצים, ולכל אחד scope, כלומר קבוצת האנשים והפרויקטים שההגדרה חלה עליהם:

| Scope | קובץ | על מי זה חל | למה משתמשים בו |
| --- | --- | --- | --- |
| User | `~/.claude/settings.json` | עליך, בכל הפרויקטים במחשב | העדפות אישיות: theme, מצב עורך, כללי הרשאות שלך |
| Shared project | `.claude/settings.json` | על כל מי שעובד בתיקייה. בריפו git עושים לו commit | הרשאות צוות, hooks, plugins ומשתני סביבה שהפרויקט צריך |
| Project local | `.claude/settings.local.json` | עליך, בפרויקט הזה בלבד | חריגות אישיות בפרויקט, וניסוי לפני ששותפים |
| Managed | `managed-settings.json` ומקורות מנוהלים אחרים | על כל מי שהארגון פורס אליו | מדיניות אבטחה ודרישות רגולציה |

`~/.claude` הוא תיקיית `.claude` בתיקיית הבית שלך, ו-`.claude` בלי `~` הוא התיקייה שבתוך הפרויקט. ב-Windows,‏ `~/.claude` הוא `%USERPROFILE%\.claude`.

התקנת Claude Code לא יוצרת אף קובץ הגדרות. את קובץ ה-user יוצר Claude Code בפעם הראשונה שמשנים ב-`/config` אפשרות שנשמרת בו, כמו ה-theme. את הקובץ המקומי הוא יוצר בפעם הראשונה שעונים "Yes, and don't ask again" על בקשת הרשאה. את קובץ הפרויקט המשותף יוצרים בעצמך ב-`.claude/settings.json`, ואת הקובץ המנוהל פורס הארגון.

Claude Code מחזיק גם קובץ נוסף, `~/.claude.json`, שהוא כותב לעצמו: סשן ההתחברות, הגדרות MCP ומצב לכל פרויקט. אין צורך לערוך אותו. פירוט של כל הקבצים בתיקייה נמצא ב[שיעור על תיקיית .claude](/advanced/claude-directory).

## איך משתפים הגדרות עם הצוות?
עושים commit ל-`.claude/settings.json`, וכל מי שמשכפל את הריפו מקבל את אותן הרשאות, hooks ו-plugins. כל חבר צוות עדיין יכול לדרוס את ההגדרות לעצמו ב-`.claude/settings.local.json`, בלי commit.

כמה דברים שכדאי לדעת לפני שמשתפים:

- **הקובץ המקומי נשאר מחוץ ל-git.** בפעם הראשונה ש-Claude Code כותב אותו בריפו, הוא מוסיף את `**/.claude/settings.local.json` לקובץ ה-excludes הגלובלי של git. אם יצרת את הקובץ ידנית, הוסף אותו ל-`.gitignore` בעצמך.
- **חלק מההגדרות מחכות לאמון בתיקייה.** כללי `permissions.allow`, רוב ערכי `env` ומרקטפלייסים של plugins מהקובץ המשותף נכנסים לתוקף רק אחרי שכל חבר צוות סימן את התיקייה כמהימנה (trust). כללי `deny` ו-`ask` חלים מיד.
- **חלק מהמפתחות לא נקראים מקובץ בריפו.** ברפרנס הרשמי, עמודת Scope מציינת לכל מפתח מאילו קבצים אפשר להגדיר אותו.

## איך משנים הגדרה?
יש שלוש דרכים: תפריט `/config`, עריכת קובץ, או ערך לסשן אחד בלבד.

### דרך /config
מריצים בתוך Claude Code:

<CommandBlock>/config</CommandBlock>

בלשונית **Config** יש רשימה קצרה של אפשרויות אישיות, כמו theme, מצב עורך ו-verbose output. זו לא רשימה של כל המפתחות. בוחרים אפשרות, ו-Claude Code שומר אותה בשבילך: רוב האפשרויות נשמרות ב-`~/.claude/settings.json`, וכמה מהן, כמו **Show tips**, נשמרות ב-`.claude/settings.local.json` של הפרויקט. אפשר גם להגדיר אפשרות אחת בלי התפריט, בתבנית `key=value`:

<CommandBlock>/config verbose=true</CommandBlock>

`/config` הוא חלק מממשק הטרמינל. בלוח הצ'אט של VS Code ובאפליקציית הדסקטופ משנים הגדרות בעריכת קובץ או בהגדרות של האפליקציה.

### בעריכת קובץ
פותחים את הקובץ של ה-scope שרוצים ומוסיפים מפתח. זו הדוגמה מהתיעוד הרשמי: מאפשרים ל-Claude Code להריץ lint ובדיקות בלי לשאול, וחוסמים קריאה של קובצי `.env`:

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(npm run lint)",
      "Bash(npm run test *)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)"
    ]
  }
}
```

השורה `$schema` מצביעה על JSON schema שפורסם להגדרות של Claude Code, ונותנת השלמה אוטומטית ובדיקה בעורכים שתומכים בזה. ה-schema יכול לפגר אחרי הגרסאות החדשות, כך שאזהרה על מפתח חדש לא אומרת בהכרח שההגדרה שגויה. את התחביר של כללי ההרשאות מסביר [השיעור על הרשאות ו-sandbox](/advanced/permissions-sandbox).

Claude Code עוקב אחרי קובצי ההגדרות וטוען אותם מחדש כשהם משתנים, כך שרוב השינויים, כולל `permissions` ו-`hooks`, חלים על הסשן הפעיל בלי הפעלה מחדש. יוצאים מהכלל כמה מפתחות שנקראים רק בתחילת סשן, כמו `model`. כדי להחליף מודל באמצע סשן משתמשים ב-`/model`.

<Callout type="warning">
קובצי ההגדרות הם JSON קפדני. הערה עם `//` או פסיק מיותר בסוף רשימה הם שגיאת תחביר, ו-Claude Code יציג Settings Error בהפעלה הבאה, עם אפשרות לתקן את הקובץ בעזרת Claude, לצאת, או להמשיך בלי ההגדרות השבורות.
</Callout>

### לסשן אחד בלבד
כדי לנסות ערך בלי לשמור אותו, מעבירים אותו כשמפעילים את Claude Code. יש שלוש אפשרויות:

- **`--settings`**: מעבירים מפתחות כ-JSON, inline או כנתיב לקובץ. הערך חל מעל קובצי user, פרויקט ו-local, ומתחת ל-managed.
- **דגל ייעודי למפתח**: לחלק מהמפתחות יש דגל משלהם, כמו `--model` למפתח `model`.
- **משתנה סביבה**: מייצאים את המשתנה המתאים לפני שמריצים `claude`, כמו `ANTHROPIC_MODEL` למפתח `model`.

לדוגמה, להפעיל סשן אחד בלי טיפים מתחת ל-spinner, בלי לשנות אף קובץ:

```bash
claude --settings '{"spinnerTipsEnabled": false}'
```

את שמות המודלים הזמינים לא כדאי לקבע בקובץ מהזיכרון. בודקים אותם ב-`/model` ובדף [Model configuration](https://code.claude.com/docs/en/model-config).

## איזו הגדרה גוברת?
כשאותו מפתח מופיע בכמה מקומות, Claude Code משתמש בערך מהרמה הגבוהה ביותר שמגדירה אותו. הסדר, מהגבוה לנמוך:

| # | רמה | קובץ או מקור | של מי |
| --- | --- | --- | --- |
| 1 | Managed settings | `managed-settings.json`,‏ MDM או קונסולת claude.ai | הארגון |
| 2 | Command line | `claude --settings` ודגלים | אתה, בסשן הזה |
| 3 | Project local | `.claude/settings.local.json` | אתה, בפרויקט הזה |
| 4 | Shared project | `.claude/settings.json` | כל מי שבפרויקט |
| 5 | User | `~/.claude/settings.json` | אתה, בכל פרויקט |

שלושה כללים שכדאי לזכור:

- **Managed גובר על הכול.** שום דבר שתגדיר, גם לא `--settings`, לא ידרוס מפתח שהארגון קבע, חוץ מכמה מפתחות אבטחה שבהם Claude Code מכבד ערך מחמיר יותר מרמה נמוכה.
- **רשימות מתמזגות.** אם `permissions.allow` מוגדר בכמה קבצים, Claude Code מאחד את הרשימות במקום לבחור אחת. לכמה מפתחות של רשימות מודלים יש כללים משלהם, שמפורטים בתיעוד.
- **משתני סביבה הם לא רמה בטבלה.** כשלהתנהגות יש גם משתנה shell וגם מפתח הגדרות, ההכרעה נקבעת לכל זוג בנפרד. בלוק `env` בתוך קובץ הגדרות הוא מפתח רגיל, ועובר לפי סדר הרמות שבטבלה.

### דוגמה: מי מחזיר את הטיפים?
נניח שהגדרת `"spinnerTipsEnabled": false` ב-`~/.claude/settings.json` כדי להסתיר את הטיפים שמתחלפים מתחת ל-spinner:

| מה קרה | התוצאה | מה אפשר לעשות |
| --- | --- | --- |
| קובץ הצוות `.claude/settings.json` מגדיר `true` | בפרויקט הזה רואים טיפים, כי פרויקט משותף גבוה מ-user | להוסיף `false` ל-`.claude/settings.local.json` באותו פרויקט |
| ה-managed settings של הארגון מגדירים `true` | רואים טיפים בכל מקום | אי אפשר לדרוס. בודקים ב-`/status` איזה מקור חל, ופונים למנהל |
| הפעלת סשן עם `--settings` ו-`true` | רואים טיפים בסשן הזה בלבד | בסשן הבא הערך שלך חוזר |

## איך מגדירים משתני סביבה בקובץ ההגדרות?
מוסיפים אותם תחת המפתח `env`. Claude Code קורא אותם ישירות מהקובץ, כך שהם חלים בכל הפעלה, לא משנה איך הופעל `claude`. זו הדוגמה מ[דף משתני הסביבה הרשמי](https://code.claude.com/docs/en/env-vars):

```json
{
  "env": {
    "API_TIMEOUT_MS": "1200000",
    "BASH_DEFAULT_TIMEOUT_MS": "300000"
  }
}
```

מה שחשוב לדעת על `env`, לפי [הרפרנס הרשמי](https://code.claude.com/docs/en/settings-reference#env):

- **הקובץ קובע על מי זה חל**, בדיוק כמו בכל מפתח אחר: user לך בכל פרויקט, קובץ הפרויקט המשותף לכל הצוות, managed לכל הארגון.
- **ערך ב-`env` גובר על אותו משתנה שייצאת ב-shell.** אי אפשר למחוק משתנה מתוך קובץ הגדרות, אבל אפשר לנטרל משתנה שמוגדר ב-shell כשמגדירים אותו כמחרוזת ריקה `""`. Claude Code מתייחס לערך ריק כלא מוגדר בבחירת ספק ה-API, ותהליכי משנה מקבלים את הערך הריק.
- **שינוי בקובץ חל על הסשן הפעיל** כשהקובץ נשמר, חוץ מפיצ'רים שקוראים את המשתנים רק בהפעלה, כמו OpenTelemetry. הסרת משתנה מהקובץ תיכנס לתוקף רק בהפעלה הבאה.
- **קובצי פרויקט לא יכולים להגדיר הכול.** משתנים שריפו לא אמור לשלוט בהם, כמו `CLAUDE_CONFIG_DIR` או `HOME`, נזרקים מקובצי פרויקט ו-local. מגדירים אותם ב-shell, בקובץ ה-user או ב-managed.

<Callout type="warning">
ערכי `env` נשמרים כטקסט גלוי בקובץ ומגיעים לכל תהליך ש-Claude Code מפעיל. אל תכתוב מפתחות API או סודות בקובץ שעושים לו commit. לפרטי התחברות ל-API הרפרנס מפנה ל-`apiKeyHelper`.
</Callout>

## אילו הגדרות נפוצות כדאי להכיר?
יש מאות מפתחות, ואין צורך להכיר את כולם. כמה שמופיעים בתיעוד ובדוגמאות הרשמיות:

| מפתח | מה הוא עושה |
| --- | --- |
| `permissions` | כללי `allow`,‏ `ask` ו-`deny` למה ש-Claude Code מריץ וקורא |
| `env` | משתני סביבה לכל סשן ולתהליכים שהוא מפעיל |
| `hooks` | פקודות שרצות באירועים קבועים (ראה [השיעור על hooks](/advanced/hooks)) |
| `language` | השפה ש-Claude עונה בה כברירת מחדל, למשל `"japanese"` |
| `spinnerTipsEnabled` | `false` מסתיר את הטיפים מתחת ל-spinner. מופיע ב-`/config` כ-**Show tips** |
| `cleanupPeriodDays` | כמה ימים לשמור תמלילי סשנים ונתוני אפליקציה אחרים לפני מחיקה. ברירת המחדל היא 30 |

לכל מפתח, [רשימת ההגדרות המלאה](https://code.claude.com/docs/en/settings-reference) מציינת את הסוג, ברירת המחדל, מאילו קבצים אפשר להגדיר אותו ודוגמה. יש גם [דף קובצי דוגמה](https://code.claude.com/docs/en/settings-example) עם קובץ אישי, קובץ צוות וקובץ ארגוני, ובאתר יש [מרכז רפרנס](/reference).

## איך בודקים מה נטען?
מריצים:

<CommandBlock>/status</CommandBlock>

בלשונית **Status** יש שורת `Setting sources` שמפרטת כל קובץ הגדרות שנטען לסשן, כמו `User settings` או `Project local settings`. כשיש managed settings, מופיע בסוגריים איך הם הגיעו למחשב. השורה לא מראה איזה קובץ סיפק כל מפתח. כדי לראות רשומות ש-Claude Code דחה, מריצים:

<CommandBlock>claude doctor</CommandBlock>

אם הגדרה לא חלה, הסיבות הנפוצות לפי התיעוד: רמה גבוהה יותר מגדירה את אותו מפתח, הקובץ לא יכול להגדיר את הערך הזה, או שהקובץ שבור.
