Advisor tool מאפשר ל-Claude Code להתייעץ במודל שני, בדרך כלל חזק יותר, ברגעי מפתח במשימה: לפני בחירת גישה, כששגיאה חוזרת, ולפני שהוא מכריז שסיים. אתה בוחר את מודל היועץ עם `/advisor`, ו-Claude מחליט מתי לפנות אליו. הכלי ניסיוני ודורש את Anthropic API.

## למה זה חשוב
ברוב המשימות הארוכות רוב הצעדים שגרתיים, ורק כמה החלטות קובעות את התוצאה. במקום להריץ את המודל החזק לאורך כל הסשן, מודל ראשי מהיר עושה את העבודה ומודל יועץ נכנס רק בנקודות ההחלטה. לפי התיעוד, זה בדרך כלל זול יותר מלהריץ את המודל החזק כל הזמן.

היועץ מתאים ל:

- refactor גדול עם הרבה צעדים.
- סשן debugging שבו אותה שגיאה חוזרת.
- משימה שאתה רוצה לבדוק באופן עצמאי לפני ש-Claude מכריז שסיים.

במשימות קצרות, שאין בהן הרבה מה לתכנן, או כשכל צעד צריך את המודל החזק, עדיף [להחליף את המודל הראשי](https://code.claude.com/docs/en/model-config).

<Callout type="warning">
ה-advisor ניסיוני. ההתנהגות, התמחור והזמינות שלו עשויים להשתנות.
</Callout>

## איך מפעילים את ה-advisor?
יש שלוש דרכים לבחור מודל יועץ:

| דרך | מה היא עושה |
| --- | --- |
| הפקודה `/advisor` | בוחרת או מחליפה יועץ באמצע סשן, ושומרת את הבחירה כברירת מחדל |
| ההגדרה `advisorModel` | ברירת מחדל קבועה בקובץ settings, בלי לפתוח סשן |
| הדגל `--advisor` | יועץ לסשן אחד בלבד, בלי לשנות את ההגדרה השמורה |

הדרך הפשוטה היא להריץ את הפקודה בלי ארגומנט. היא פותחת רשימה של מודלי היועץ הזמינים:

<CommandBlock>/advisor</CommandBlock>

אחרי הבחירה Claude Code מאשר עם `Advisor set to` ושם המודל. הבחירה נשמרת ב-`advisorModel` בהגדרות המשתמש ונשארת גם בסשנים הבאים, חוץ ממקרים מסוימים שבהם היא חלה רק על הסשן הנוכחי (הפירוט ב-[settings reference](https://code.claude.com/docs/en/settings-reference#advisormodel)). אפשר גם להעביר את המודל ישירות כארגומנט, ובגרסאות עדכניות `/advisor` עובד גם במצב לא-אינטראקטיבי עם `-p`, ב-Agent SDK ובאפליקציית הדסקטופ. כשסשן עם יועץ מתחיל, מופיעה ההודעה:

```text
Advisor Tool (experimental) is on and may use more tokens · /advisor
```

### איך מגדירים יועץ בלי לפתוח סשן?
כותבים את `advisorModel` ב[קובץ settings](https://code.claude.com/docs/en/settings). הערך הוא alias של משפחת מודלים או model ID מלא:

```json
{
  "advisorModel": "<model>"
}
```

לסשן אחד בלבד מפעילים עם הדגל. Claude Code משתמש בו במקום ההגדרה השמורה, והדגל לא מופיע ב-`claude --help`. אם המודל הראשי לא תומך ביועץ, המודל שביקשת לא יכול לשמש כיועץ, או שרשימת `availableModels` של הארגון לא מתירה אותו, Claude Code יוצא עם שגיאה כבר בהפעלה:

```bash
claude --advisor <model>
```

שמות המודלים וה-aliases מתחלפים לעיתים קרובות. את הרשימה העדכנית מוצאים ברשימה של `/advisor` ובדף [Model configuration](https://code.claude.com/docs/en/model-config).

## איך בוחרים מודל יועץ?
הכלל: היועץ חייב להיות לפחות חזק כמו המודל הראשי. לא כל צירוף מתקבל, ולכל מודל ראשי יש רשימה משלו של יועצים מותרים. הטבלה המלאה נמצאת [בדף הרשמי](https://code.claude.com/docs/en/advisor#choose-an-advisor-model).

כמה דברים שכדאי לדעת:

- **צירוף שנדחה:** Claude Code בודק את הצירוף לפני שליחת בקשה, וה-API בודק שוב. יועץ שהטבלה מסמנת כנדחה לא מצורף, והפקודה `/advisor` והתראה מציגות את זה. יועץ שה-API מסרב לו מצורף, נדחה, ומשם השיחה ממשיכה בלי יועץ ובלי הודעת שגיאה. אחרי שבוחרים יועץ מתאים, השינוי נכנס לתוקף אחרי `/clear` או `/compact` ובסשנים חדשים.
- **שמירה לעתיד:** Claude Code עדיין שומר יועץ שהמודל הראשי הנוכחי לא תומך בו. היועץ נכנס לפעולה אחרי שעוברים עם `/model` למודל ראשי מתאים. אם ה-API כבר סירב ליועץ בשיחה הנוכחית, הוא נשאר כבוי עד `/clear` או `/compact`.
- **Subagents:** הם יורשים את היועץ המוגדר, ובודקים את הצירוף מול המודל שלהם.
- **מדיניות ארגון:** Claude Code לא מפעיל יועץ שרשימת `availableModels` של הארגון לא מתירה. בוחרים מודל מותר עם `/advisor`.

## מתי Claude מתייעץ ביועץ?
Claude מחליט בעצמו. הוא נוטה לפנות ליועץ לפני שהוא מתחייב לגישה, כששגיאה חוזרת, ולפני שהוא מכריז שהמשימה הסתיימה. התזמון נקבע על ידי המודל, לא לפי כללים קבועים.

אין הגדרה שמגבילה או מכריחה התייעצויות. כדי לבקש התייעצות, כותבים את זה בפרומפט, כמו כל בקשה לכלי. זו הדוגמה מהתיעוד:

```text
consult the advisor before you continue
```

רוצה יותר התייעצויות או פחות במשימה מסוימת? כתוב את זה בהוראות שלך.

## מה רואים בזמן התייעצות?
בזמן הקריאה, התמליל מציג שורת `Advising` עם שם מודל היועץ. כשהתשובה חוזרת, השורה מראה אחת משתי תוצאות:

| תוצאה | מה רואים |
| --- | --- |
| Reviewed | השורה מאשרת שהיועץ עבר על השיחה. אם הוא החזיר הנחיות קריאות, לוחצים `Ctrl+O` כדי לקרוא אותן |
| Declined | השורה אומרת `Advisor declined to advise on this request`. אם היועץ נתן סיבה, `Ctrl+O` מציג אותה |

Claude בדרך כלל מיישם את ההנחיות, אבל לא בעיוורון. אם צעד שהיועץ המליץ עליו נכשל, או שתוכן הקבצים סותר את העצה, Claude מציג את הסתירה במקום לבצע את ההנחיה כמו שהיא.

## כמה זה עולה?
בכל התייעצות מודל היועץ קורא את כל השיחה, ולכן הוא צורך טוקנים לפי התעריף שלו, בנוסף למודל הראשי:

- **חיוב API:** משלמים את תעריפי ה-input וה-output של מודל היועץ.
- **מנוי:** השימוש של היועץ נספר במגבלות התוכנית. בחלק מהתוכניות, מודלים מסוימים כיועץ מחויבים ב-usage credits. הפרטים בדף [Model configuration](https://code.claude.com/docs/en/model-config).

השימוש של היועץ נכלל בסיכומי הסשן שמציגה הפקודה `/usage`.

### האם ה-advisor שובר את ה-prompt cache?
לא. הפעלה או כיבוי של היועץ באמצע סשן לא מבטלים את ה-prompt cache של המודל הראשי, בניגוד להחלפת מודל. ההנחיות שהיועץ מחזיר נשמרות ב-cache כחלק מהתמליל. לעומת זאת, הקריאה של היועץ עצמו לא נשמרת ב-cache: כל התייעצות מעבדת את כל התמליל מחדש.

## מה צריך כדי להשתמש ב-advisor?
- **Anthropic API בלבד:** היועץ רץ בצד השרת של Anthropic. הוא לא זמין ב-Amazon Bedrock,‏ Claude Platform on AWS,‏ Google Cloud's Agent Platform או Microsoft Foundry. דרך LLM gateway, הזמינות תלויה בכך שה-gateway מעביר את הבקשה כמו שהיא ל-Anthropic API.
- **מודל ראשי נתמך:** לא כל מודל ראשי תומך ביועץ. הרשימה בדף הרשמי.
- **משיכת feature flags:** Claude Code מפעיל את היועץ דרך feature flag שהוא מושך מ-Anthropic. אם מוגדר משתנה שמכבה את המשיכה, כמו `DISABLE_TELEMETRY`, היועץ נשאר כבוי.

## איך מכבים את ה-advisor?
מריצים את הפקודה, או בוחרים **No advisor** ברשימה של `/advisor`:

<CommandBlock>/advisor off</CommandBlock>

כדי לנטרל את הכלי לגמרי, מגדירים את משתנה הסביבה `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`. אז הפקודה `/advisor` לא זמינה, ההגדרה `advisorModel` לא נלקחת בחשבון, והדגל `--advisor` מתקבל אבל לא עושה כלום.

## מתי advisor ומתי פיצ'ר אחר?
היועץ הוא אחת מכמה דרכים לשלב מודלים. בוחרים לפי השאלה מתי המודל השני צריך להיכנס:

| גישה | מתי המודל השני רץ | איך זה מתחיל |
| --- | --- | --- |
| Advisor tool | בנקודות החלטה באמצע המשימה | Claude קורא לו כשהוא צריך הנחיה |
| [Subagent](/advanced/subagents) עם `model` מוגדר | לאורך כל תת-המשימה שהועברה אליו | Claude מעביר אליו משימה, או שאתה מפעיל אותו |
| `/model` | מהבקשה הבאה והלאה | אתה מחליף מודל |

<Callout type="tip">
ההבדל המרכזי: היועץ תמיד מקבל את כל השיחה ו-Claude שולט בתזמון. אם אתה רוצה יותר שליטה או תצורה אחרת, שקול subagent או החלפת מודל.
</Callout>
