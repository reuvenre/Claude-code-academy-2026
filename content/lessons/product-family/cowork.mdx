Claude Cowork הוא דרך עבודה עם Claude שבה מאצילים משימה שלמה במקום לנהל שיחה. מתארים תוצר, מצביעים על תיקייה ועל אפליקציות מחוברות, ו-Claude מתכנן, מבצע ומחזיר קובץ גמור. Chat מיועד לחשיבה משותפת, Claude Code לפיתוח תוכנה, ו-Cowork לעבודת ידע רב-שלבית.

## למה זה חשוב
הרבה עבודה יומיומית היא לא שאלה אלא ביצוע: לאסוף נתונים מכמה מקורות, לבנות מסמך, לעדכן גיליון, לחזור על דוח כל שבוע. בצ'אט אתה מחבר את השלבים בעצמך, תור אחרי תור. ב-Cowork מסבירים פעם אחת מה צריך לצאת, וחוזרים לבדוק את התוצאה.

לפי Claude Academy, ההרגל שכדאי לשנות הוא לפנות ל-Cowork עם עבודה **שהיית עושה בעצמך**, ולא עם דברים שהיית רק שואל עליהם.

## מה ההבדל בין Chat,‏ Cowork ו-Claude Code?
שלושתם אותו Claude, בשלוש צורות עבודה. לפי Claude Academy: ב-Chat חושבים עם Claude, ל-Cowork מאצילים, וב-Claude Code בונים תוכנה.

| | Chat | Cowork | Claude Code |
| --- | --- | --- | --- |
| צורת העבודה | דיאלוג, תור אחרי תור | מאצילים משימה ובודקים תוצר | סביבת פיתוח בתוך בסיס הקוד |
| המטרה שלך | עדיין מגבש אותה | תוצר ברור | קוד שעובד ונשלח |
| היקף העבודה | כמה הודעות הלוך ושוב | רב-שלבי, כמה מקורות, זמן ריצה ארוך | שינויים בקוד, בדיקות, git |
| התפקיד שלך | נוכח בכל תור | מתאר פעם אחת וחוזר לבדוק | מנחה, מאשר ובודק שינויים |
| התוצר | טקסט לקריאה או להעתקה | קובץ גמור או פעולה שבוצעה | קוד, commits ו-PRs |

עמודות Chat ו-Cowork מבוססות על Claude Academy. עמודת Claude Code מבוססת על ה-Academy ("סביבת פיתוח מלאה בתוך בסיס הקוד, עם גישה לטרמינל ול-git") ועל התיעוד של Claude Code.

לפי Claude Academy, ‏Cowork רץ על אותו מנוע סוכני של Claude Code: לולאה שבה Claude מתכנן, עובד עם כלים ובודק את עצמו. ההבדל הוא שב-Cowork הלולאה עובדת על הקבצים והאפליקציות שלך, ולא על בסיס קוד.

## למי Cowork מתאים?
Cowork מיועד בעיקר לעובדי ידע שמייצרים תוצרים: מסמכים, מצגות, גיליונות, סיכומי מחקר ודוחות חוזרים. לפי Claude Academy, רוב עובדי הידע יעבדו בעיקר ב-Chat וב-Cowork, ו-Claude Code מיועד למפתחים שכותבים ושולחים תוכנה.

לפי Claude Academy, משימה טובה ל-Cowork היא משימה עם אחד או יותר מהמאפיינים האלה:

- **רב-שלבית**: כמה צעדים שתלויים זה בזה.
- **מייצרת קובץ**: מסמך, מצגת או גיליון בסוף.
- **משתמשת בכלים**: מייל, יומן, Slack, אחסון בענן או אתר.

ואם אותו תהליך חוזר כל שבוע או כל חודש, אפשר גם לתזמן אותו (ראה בהמשך).

## איפה עובדים עם Cowork?
לפי Claude Academy אפשר להשתמש ב-Cowork באפליקציית Claude Desktop ‏(Mac ו-Windows), ברשת ובאפליקציית הטלפון, ונדרשת תוכנית Claude בתשלום. בתיעוד של Claude Code, אפליקציית Desktop מתוארת עם שלוש לשוניות: **Chat**, ‏**Cowork** ו-**Code**. פרטים נוספים בשיעור [Claude Code Desktop](/pro/desktop).

כשהעבודה על קבצים במחשב שלך, מתחילים מאפליקציית Desktop. משימה שמתחילה ברשת או בטלפון מגיעה ל-connectors, אבל לא לתיקיות המקומיות.

## איך נראית משימה ב-Cowork?
משימה ב-Cowork דומה לתדרוך של עמית שיוצא לעבוד ואז חוזר עם תוצר:

<StepList>

1. **בוחרים איפה העבודה נמצאת.** לוחצים על **Work in a project or folder** ובוחרים תיקייה שמוקדשת לפרויקט אחד. ל-Claude יש בה הרשאות קריאה וכתיבה, והוא שומר בה את התוצרים.
2. **מפעילים connectors רלוונטיים.** למשל מייל, יומן, Slack או Google Drive.
3. **כותבים פרומפט טוב.** מציינים את התוצר (פורמט ואורך), את מקורות הקלט (תיקייה, ערוצים, טווח תאריכים), ואת הניואנסים שרק אתה יודע.
4. **עונים על שאלות ההבהרה.** ברוב המשימות שאינן טריוויאליות Claude שואל שאלה או שתיים לפני שהוא מתחיל, כדי לסגור פערים בהבנה.
5. **מכוונים תוך כדי.** אם Claude פונה לכיוון לא נכון, מתערבים מיד. לא מחכים לסוף.
6. **בודקים את התוצר.** הקובץ נמצא בתיקייה. בודקים שהוא עונה על המטרה, שהעובדות נכונות, ושאין פרטים שאי אפשר לעקוב אחריהם למקור.

</StepList>

זה פרומפט ההתחלה ש-Claude Academy מציע כדי לבדוק שההגדרה עובדת:

```text
Take a look at everything in this folder and write me a brief on what you've learned — what's in the folder, how the documents relate to one another, any surprising insights, or other information you think would be pertinent to share.
```

<Callout type="tip">
אם הטיוטה כמעט נכונה, בקש מ-Claude לתקן אותה במקום להתחיל מחדש. אם היא שגויה בדבר מהותי, בדרך כלל חסר בפרומפט הקשר חשוב. הוסף אותו ובקש להתאים.
</Callout>

## איך נותנים ל-Cowork הקשר קבוע?
יש שתי שכבות של הקשר שנשמרות בין משימות:

| שכבה | מה היא | מתי משתמשים |
| --- | --- | --- |
| Global instructions | תדריך קבוע ב-Settings שחל על כל סשן, כולל משימות מתוזמנות | מי אתה, קיצורים שאתה משתמש בהם, איך אתה אוהב לקבל תוצרים |
| Projects | סביבת עבודה לזרם עבודה אחד: הנחיות, משימות מתוזמנות, תיקיות או קישורים, וזיכרון ש-Claude בונה לבד | לקוח, דוח חוזר, השקה או יוזמה |

ההבדל המרכזי: מחוץ ל-project כל סשן מתחיל מחדש, חוץ מה-global instructions. בתוך project, כל שיחה מוסיפה למה ש-Claude יודע על אותו זרם עבודה. יוצרים project מ-**Projects** בסרגל הצד, ואז **New project**.

## מה עושים plugins ב-Cowork?
Plugin הוא חבילה של כמה skills סביב תפקיד או תהליך, יחד עם ה-connectors וה-subagents שהם צריכים. לפי Claude Academy, ‏Anthropic מפרסמת plugins לתפקידים נפוצים, כמו כספים, משפטים, מכירות ושיווק.

- **התקנה:** ב-**Customize → Plugins** בוחרים plugin, לוחצים **Install** ומאשרים את ה-connectors שלו.
- **התאמה:** נכנסים ל-plugin שהותקן ולוחצים **Customize**. נפתחת משימת Cowork שבה מתאימים אותו לתבניות ולדוגמאות של הצוות.
- **בנייה:** אפשר לבנות plugin חדש בעבודה משותפת עם Cowork, ולשתף אותו עם הצוות.

לפי התיעוד של Claude Code, ‏[לשונית Cowork לוקחת את ה-skills, ה-plugins וה-connectors שלה מההגדרות של Customize](https://code.claude.com/docs/en/desktop), שמסתנכרנות דרך חשבון claude.ai. היא לא קוראת אותם מתיקיית `~/.claude` של ה-CLI. על plugins ב-Claude Code עצמו, ראה [Plugins](/advanced/plugins).

## איך Cowork עובד עם Claude in Chrome?
Claude in Chrome מאפשר ל-Cowork לעבוד עם אתרים שאין להם connector: דשבורדים פנימיים, פורטלים של ספקים ואפליקציות מאחורי התחברות. Claude אוסף את הנתונים בדפדפן, ואז בונה את התוצר ב-Cowork, באותה שיחה.

שני דברים שכדאי לדעת:

- **צריך להיות מחובר מראש.** Claude לא מתחבר לאתר בשבילך. הוא עובד בסשן הדפדפן שכבר מחובר.
- **Claude רואה מה שאתה רואה.** באתרים רגישים כדאי לצמצם את מה ש-Claude יכול לעשות, ולבדוק כל פעולה לפני שמאשרים.

לפי Claude Academy, ייתכן ש-Claude in Chrome לא יהיה זמין בחלק מתוכניות Enterprise. השימוש ב-Chrome מתוך Claude Code מוסבר בשיעור [Claude in Chrome](/pro/chrome).

## איך מתזמנים משימות חוזרות?
לפי Claude Academy, ב-Cowork מקלידים `/schedule`, מתארים את המשימה ואת התדירות, ו-Claude מנסח פרומפט שאתה בודק ומאשר. הדרך שמומלצת ב-Claude Academy: לבצע את המשימה פעם אחת, לוודא שהתוצר טוב, ואז להקליד `/schedule` כדי להפוך את אותו תהליך לחוזר.

איפה המשימה רצה תלוי במה שהיא צריכה:

| המשימה צריכה | איפה היא רצה |
| --- | --- |
| רק connectors | מרחוק, בזמן שנקבע. המחשב לא צריך להיות דלוק |
| קבצים או אפליקציות במחשב | במחשב שלך. אפליקציית Desktop צריכה להיות פתוחה, ואם המחשב כבוי המשימה תרוץ כשתחזור |

<Callout type="warning">
משימה מתוזמנת רצה כשאתה לא מסתכל. עד שאתה בטוח בה, בקש ממנה להכין טיוטה לבדיקה, ולא לשלוח בשמך. ואת ההרצה הראשונה עדיף לעשות על עותק של הנתונים.
</Callout>

תזמון משימות ב-Claude Code עובד אחרת. ראה [משימות מתוזמנות](/pro/scheduled).

## אילו הרשאות יש ל-Cowork?
כשבוחרים תיקייה, מאשרים ל-Claude לקרוא ולכתוב בה. בתוך המשימה יש שני מצבי הרשאה:

| מצב | מה קורה |
| --- | --- |
| **Ask before acting** (ברירת מחדל) | Claude עוצר לאישור לפני כל פעולה שיוצאת החוצה: שליחת מייל, פרסום הודעה, שיתוף קובץ |
| **Act without asking** | Claude לא עוצר לפעולות האלה. מתאים רק לכלים ולמשימות שאתה סומך עליהם |

בשני המצבים Claude תמיד שואל לפני מחיקה סופית של קובץ, ואי אפשר לדלג על כך.

הרגלים שמצמצמים טעויות, לפי Claude Academy:

- **תיקייה ייעודית**, ולא Documents או Desktop כולם.
- **גיבוי** של קבצים שאין להם תחליף, במקום ש-Cowork לא מגיע אליו.
- **פעלים מדויקים בפרומפט**: "הסר את הסעיף מהטיוטה אבל השאר את הקובץ", ולא רק "חתוך".
- **גבולות מפורשים**: "רק החוזים שנסגרו ברבעון השלישי", "רק טיוטה, אל תשלח לאף אחד".
- **קריאה של כל בקשת אישור** לפני שלוחצים עליה.

Cowork פחות מתאים לתהליכים מפוקחים שדורשים audit trail: לפי Claude Academy, פעילות Cowork לא נרשמת ב-audit logs ולא בייצוא נתונים.

<Callout type="note">
שמות המודלים מתחלפים לעיתים קרובות, ולכן לא נקבע אותם כאן. לרשימה העדכנית ראה [Model configuration](https://code.claude.com/docs/en/model-config).
</Callout>

## מתי לבחור Cowork ומתי Claude Code?
הכלל הפשוט: אם התוצר הוא **תוכנה**, בוחרים Claude Code. אם התוצר הוא **מסמך, גיליון, מחקר או פעולה באפליקציה**, בוחרים Cowork.

| בחר Claude Code כש... | בחר Cowork כש... |
| --- | --- |
| מתקנים באג או מוסיפים פיצ'ר | מכינים מסמך, מצגת או גיליון מתוך תיקיית קבצים |
| מעדכנים dependencies או מריצים בדיקות | אוספים מחקר מכמה מקורות לתדריך אחד |
| פותחים pull request | מבצעים פעולה בדפדפן או באפליקציה מחוברת |
| צריך גישה לטרמינל ול-git | רוצים דוח חוזר שמוכן לבד כל שבוע |

גם התיעוד של Claude Code עושה את אותה הפרדה. [Dispatch](https://code.claude.com/docs/en/desktop#sessions-from-dispatch) הוא שיחה קבועה בלשונית Cowork, שאליה שולחים משימות מהטלפון. כשמבקשים ממנו במפורש, או כשהוא מזהה שהמשימה היא עבודת פיתוח, Dispatch פותח סשן בלשונית Code. משימות שבדרך כלל מנותבות ל-Code: תיקון באג, עדכון dependencies, הרצת בדיקות או פתיחת PR. מחקר, עריכת מסמכים ועבודה על גיליונות נשארים ב-Cowork. לפי התיעוד, Dispatch דורש תוכנית Pro או Max ואינו זמין ב-Team או Enterprise.
