כל הודעה ב-Claude Code שולחת מחדש את כל השיחה, ולכן הקשר גדול עולה יותר טוקנים. בודקים צריכה עם `/usage`, רואים מה ממלא את החלון עם `/context`, ומנקים עם `/clear` או `/compact`. prompt caching חוסך אוטומטית, אבל החלפת מודל באמצע משימה שוברת אותו.

## למה זה חשוב
עלות הטוקנים גדלה עם גודל ההקשר: ככל ש-Claude מעבד יותר הקשר, צורכים יותר טוקנים. זה נכון גם אם אתה משלם לפי API וגם אם אתה על מנוי עם מגבלות שימוש. סשן שפתוח כבר שעות יכול לצרוך הרבה יותר מהמכסה ממה שנראה לך, גם כששואלים בו שאלה של שורה אחת. כמה הרגלים פשוטים שומרים על ההקשר קטן ועל הצריכה נמוכה.

## איך בודקים כמה צרכת?
מקלידים בתוך הסשן:

<CommandBlock>/usage</CommandBlock>

לפי [רשימת הפקודות הרשמית](https://code.claude.com/docs/en/commands), ‏`/cost` ו-`/stats` הם כינויים (aliases) של אותה פקודה. מה רואים במסך:

- **בלוק Session:** סטטיסטיקות טוקנים של הסשן הנוכחי והערכת עלות בדולרים. Claude Code מחשב את ההערכה מקומית, והיא מיועדת בעיקר למשתמשי API. לחיוב מדויק בודקים בדף Usage ב-[Claude Console](https://platform.claude.com/usage).
- **שורת `Prompt cache (main)`:** כמה מהקלט הגיע מהמטמון, כמה פספוסים (misses) היו, והאם המטמון "חם" עכשיו.
- **למנויי Pro,‏ Max,‏ Team ו-Enterprise:** פסי שימוש מול מגבלות התוכנית, ופירוט של מה צורך מהמכסה, כולל skills,‏ subagents ושרתי MCP. התנהגויות כמו הקשר ארוך או פספוסי מטמון מסומנות כשהן אחראיות ל-10% או יותר מהשימוש האחרון.

הנתונים ב-Session מתאפסים כש-`/clear` פותח סשן חדש. בפירוט התוכנית לוחצים `d` או `w` כדי לעבור בין 24 השעות האחרונות ל-7 הימים האחרונים. הנתונים מחושבים מהיסטוריית הסשנים במחשב הזה בלבד.

<Callout type="note">
את המחירים, התוכניות והמודלים עצמם לא נפרט כאן, כי הם מתחלפים. תמחור מנויים נמצא ב-[claude.com/pricing](https://claude.com/pricing), ופרטי המודלים ב-[model-config](https://code.claude.com/docs/en/model-config).
</Callout>

## מה ממלא את חלון ההקשר?
חלון ההקשר (context window) הוא כל מה ש-Claude "רואה" בבקשה אחת. לפי [דף חלון ההקשר](https://code.claude.com/docs/en/context-window), הוא מתמלא בשני שלבים:

- **לפני שהקלדת משהו:** CLAUDE.md,‏ auto memory, שמות כלי MCP ותיאורי skills. גם הגדרות כמו output style יכולות להוסיף כאן.
- **תוך כדי עבודה:** כל קובץ ש-Claude קורא נוסף להקשר, וכך גם תוצאות כלים והודעות השיחה.

כדי לראות את המצב האמיתי בסשן שלך, מריצים:

<CommandBlock>/context</CommandBlock>

הפקודה מציגה את השימוש בהקשר כרשת צבעונית, עם פירוט לפי קטגוריה והצעות לייעול. היא מראה גם אילו קובצי CLAUDE.md ו-auto memory נטענו.

## מה זה prompt caching, במילים פשוטות?
המודל לא זוכר כלום בין בקשות, ולכן בכל הודעה Claude Code שולח מחדש את כל ההקשר: system prompt, הקשר הפרויקט, כל ההודעות ותוצאות הכלים, וההודעה החדשה בסוף. רוב הבקשה זהה לבקשה הקודמת. לפי [דף prompt caching](https://code.claude.com/docs/en/prompt-caching), המטמון (cache) מאפשר לא לעבד מחדש את החלק שלא השתנה: הוא מחויב בתעריף מטמון נמוך יותר, ורק החדש מעובד במלואו.

ההתאמה נעשית לפי תחילת הבקשה (prefix), והיא חייבת להיות מדויקת. שינוי במקום כלשהו בתחילת הבקשה מחייב לעבד מחדש את כל מה שאחריו. לכן Claude Code מסדר כל בקשה כך שמה שמשתנה לעיתים רחוקות בא ראשון:

| שכבה | מה יש בה | מתי משתנה |
| --- | --- | --- |
| System prompt | הוראות ליבה, הגדרות כלים | כשסט הגדרות הכלים משתנה |
| הקשר הפרויקט | CLAUDE.md,‏ auto memory, rules בלי `paths:` | בתחילת סשן, או אחרי `/clear` או `/compact` |
| השיחה | ההודעות שלך, תשובות Claude, תוצאות כלים | בכל תור |

Claude Code מנהל את המטמון לבד. לא צריך להפעיל אותו.

### כמה זמן המטמון נשמר?
המטמון פג אחרי זמן ללא פעילות. כל בקשה שפוגעת בו מאפסת את השעון, כך שהוא נשאר "חם" כל עוד עובדים. בשיחה הראשית, בתוכנית מנוי במסגרת השימוש הכלול, זמן החיים הוא שעה. כשעוברים ל-usage credits, או עובדים עם מפתח API או ספק ענן, הוא חמש דקות כברירת מחדל. לכן ההודעה הראשונה אחרי הפסקה ארוכה איטית ויקרה יותר.

## מה שובר את המטמון?
הפעולות האלה גורמות לבקשה הבאה לפספס חלק מהמטמון או את כולו. מקבלים תור אחד איטי ויקר יותר, ואחריו המטמון נבנה מחדש:

- **החלפת מודל** עם `/model`: לכל מודל יש מטמון משלו.
- **שינוי effort level:** ברוב המודלים, לכל רמה יש מטמון משלה.
- **הפעלת fast mode** בפעם הראשונה בשיחה.
- **חיבור או ניתוק שרת MCP**, כשהכלים שלו נטענים מראש ולא נדחים (deferred).
- **הפעלה או כיבוי של plugin** שמספק שרתי MCP, באותם תנאים.
- **חסימה של כלי שלם** בכלל deny, כשחיפוש הכלים לא פעיל.
- **דחיסת השיחה** עם `/compact` או אוטומטית: היסטוריית השיחה מוחלפת בסיכום.
- **הרבה תמונות:** כשמגיעים למגבלה, Claude Code מסיר תמונות ישנות, וזה משנה את ההודעות.
- **שדרוג Claude Code:** השיחה הראשונה אחרי שדרוג בונה את המטמון מההתחלה.

פעולות ששומרות על המטמון: עריכת קבצים בפרויקט, עריכת CLAUDE.md באמצע סשן, החלפת permission mode, הפעלת skills ופקודות, `/rewind`, והפעלת subagent.

<Callout type="tip">
בוחרים מודל ו-effort בתחילת הסשן, ושומרים את `/compact` להפסקות טבעיות בין משימות. ככל שמשנים פחות באמצע משימה, יותר מהבקשות נענות מהמטמון.
</Callout>

## מתי /clear ומתי /compact?
`/clear` מתחיל שיחה חדשה עם הקשר ריק. `/compact` מסכם את השיחה ומשאיר אותך באותה עבודה.

| מצב | מה מריצים |
| --- | --- |
| עוברים למשימה שאין לה קשר לקודמת | `/clear` |
| ממשיכים באותה משימה, אבל ההקשר התנפח | `/compact` |
| הלכת בכיוון שרוצים לנטוש לגמרי | `/rewind` לתור מוקדם יותר |

שים לב להבדל בעלות. `/compact` קורא את כל השיחה כדי לסכם אותה, ולכן דחיסה של הקשר גדול היא בעצמה בקשה גדולה. כשהמטמון חם, הבקשה הזו קוראת את רוב ההיסטוריה מהמטמון ועולה רק חלק ממה שגודל ההקשר מרמז. `/clear` לא עולה כלום. אם רוצים לחזור לשיחה אחר כך, מריצים `/rename` לפני הניקוי ו-`/resume` כדי לחזור אליה.

אפשר לכוון את הסיכום עם הוראות. זו הדוגמה מהתיעוד הרשמי:

<CommandBlock>/compact Focus on code samples and API usage</CommandBlock>

כשהחלון מתקרב למגבלה, Claude Code דוחס אוטומטית, כך שחלון מלא לא מסיים את הסשן. עדיף להריץ `/compact` בעצמך בנקודת מעבר, ולא לחכות שהדחיסה האוטומטית תקרה באמצע משימה.

<Callout type="warning">
אחרי הפסקה ארוכה מזמן החיים של המטמון, `/compact` מעבד מחדש את כל ההיסטוריה בלי מטמון. זה המצב שבו הוא עולה הכי הרבה. אם אתה רוצה התחלה חדשה ולא המשכיות, עדיף `/clear`.
</Callout>

## אילו הרגלים חוסכים טוקנים?
אלה ההמלצות מהתיעוד הרשמי, בקיצור:

- **לנקות בין משימות:** הקשר ישן מבזבז טוקנים בכל הודעה שאחריו.
- **להתאים מודל למשימה:** מחליפים עם `/model`. ההמלצות המעודכנות לפי מודל נמצאות ב-[model-config](https://code.claude.com/docs/en/model-config).
- **להוריד effort במשימות פשוטות:** עם `/effort` או ב-`/model`. טוקני thinking מחויבים כטוקני פלט.
- **לכבות שרתי MCP שלא בשימוש:** מריצים `/mcp`. כלי CLI כמו `gh` חסכוניים יותר בהקשר.
- **להעביר הוראות מ-CLAUDE.md ל-skills:** CLAUDE.md נטען בכל סשן, ו-skills נטענים רק כשמפעילים אותם. היעד: CLAUDE.md מתחת ל-200 שורות.
- **להעביר פעולות רועשות ל-subagents:** הרצת בדיקות או קריאת לוגים נשארת בהקשר של ה-subagent, ורק סיכום חוזר אליך.
- **לכתוב פרומפטים ספציפיים:** בקשה מעורפלת גורמת לסריקה רחבה של הקוד.
- **לעצור מוקדם:** לוחצים `Esc` כש-Claude הולך לכיוון הלא נכון, ומשתמשים ב-plan mode למשימות מורכבות.

ההבדל בין פרומפט מעורפל לספציפי, בדוגמה מהתיעוד:

```text
improve this codebase
```

```text
add input validation to the login function in auth.ts
```

הראשון גורם לסריקה רחבה. השני מאפשר ל-Claude לעבוד עם מעט קריאות קבצים.
