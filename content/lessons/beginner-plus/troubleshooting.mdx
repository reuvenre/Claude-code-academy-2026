import { CommandBlock, Callout, StepList } from "@/components/lesson";

כשמשהו לא עובד ב-Claude Code, מריצים `/doctor` בתוך הסשן, או `claude doctor` מה-shell אם `claude` לא עולה בכלל. אחר כך מזהים את סוג התקלה: התקנה והתחברות, הגדרות שלא נטענות, שגיאות API או ביצועים. לכל סוג יש כלי אבחון משלו, כמו `/context`,‏ `/status` ו-`/mcp`.

## למה זה חשוב
רוב התקלות ב-Claude Code חוזרות על עצמן, ולרובן יש פתרון מתועד. כשמתחילים באבחון במקום בניחוש, מגלים מהר אם הבעיה אצלך, בהגדרות, ברשת או בצד השרת. זה חוסך התקנות מחדש מיותרות ושעות של חיפוש.

## איך מתחילים לאבחן?
מתחילים בבדיקה האוטומטית. אם Claude Code עולה, מקלידים בתוך הסשן:

<CommandBlock>/doctor</CommandBlock>

`/doctor` בודק את ההתקנה, ההגדרות, ההרחבות והשימוש בחלון ההקשר, ומציע תיקונים. הוא מחיל תיקון רק אחרי שאתה מאשר.

אם `claude` לא עולה בכלל, מריצים מה-shell:

<CommandBlock>claude doctor</CommandBlock>

`claude doctor` מדפיס אבחון של ההתקנה וההגדרות בלי לפתוח סשן, ולא משנה דבר. הוא מראה גם [קובצי הגדרות לא תקינים](https://code.claude.com/docs/en/debug-your-config#check-resolved-settings).

## איך יודעים לאיזה סוג שייכת התקלה?
התיעוד הרשמי מחלק את התקלות לפי המקום שבו נתקעת. מוצאים את הסימפטום בטבלה ועוברים לסקשן המתאים:

| מה רואים | סוג התקלה | איפה הפתרון |
| --- | --- | --- |
| `command not found`, התקנה נכשלת, שגיאות PATH או TLS | התקנה | [שיעור ההתקנה](/beginner/installation) ו-[מדריך תקלות ההתקנה](https://code.claude.com/docs/en/troubleshoot-install) |
| לולאת התחברות, שגיאת OAuth,‏ `403 Forbidden` | התחברות | הסקשן על התחברות בהמשך השיעור |
| הגדרות לא חלות, שרתי MCP לא נטענים | הגדרות | הסקשן על הגדרות שלא נטענות |
| `API Error: 5xx`,‏ `529 Overloaded`,‏ `429` | שגיאות API | טבלת השגיאות הנפוצות |
| צריכת CPU או זיכרון גבוהה, תקיעות, איטיות | ביצועים | הסקשן על ביצועים ותקיעות |

<Callout type="note">
`command not found: claude` אחרי שההתקנה הסתיימה אומר שהתיקייה של `claude` לא נמצאת ב-PATH. הפתרון לכל מערכת הפעלה מופיע ב[שיעור ההתקנה](/beginner/installation).
</Callout>

## אילו פקודות עוזרות לראות מה קורה בסשן?
כשמשהו שהגדרת לא עובד, בדרך כלל הקובץ לא נטען, נטען ממקום אחר ממה שחשבת, או שקובץ אחר דרס אותו. הפקודות האלה מראות [מה Claude Code באמת טען](https://code.claude.com/docs/en/debug-your-config):

| פקודה | מה היא מציגה |
| --- | --- |
| `/context` | כל מה שתופס את חלון ההקשר: system prompt, כלים, כלי MCP,‏ memory files,‏ skills והודעות |
| `/status` | מקורות ההגדרות הפעילים, כולל האם יש הגדרות מנוהלות של הארגון |
| `/mcp` | שרתי MCP שמוגדרים, מצב החיבור שלהם והאם אישרת אותם בפרויקט |
| `/memory` | המיקומים של קובצי ההנחיות, עם אפשרות לפתוח אותם בעורך |
| `/permissions` | כללי allow ו-deny שבתוקף כרגע |
| `/debug [issue]` | מפעיל רישום debug לסשן ומבקש מ-Claude לאבחן לפי הלוג ונתיבי ההגדרות |

מריצים `/context` קודם. הוא מראה אם CLAUDE.md, הכללים ותיאורי ה-skills בכלל נטענו.

## למה הגדרה או CLAUDE.md לא נטענים?
בודקים שלושה דברים: שהקובץ נטען, שאין scope שדורס אותו, ושהוא נמצא במקום הנכון.

- **CLAUDE.md לא מופיע ב-`/context`:** בודקים את המיקום שלו. CLAUDE.md בתת-תיקייה נטען רק כש-Claude קורא קובץ באותה תיקייה, לא בתחילת הסשן.
- **CLAUDE.md נטען אבל Claude לא ממלא הוראה:** הבעיה כנראה בניסוח. הוראות מעורפלות, סותרות, או בקובץ ארוך מדי מתמלאות פחות. חזור לשיעור [CLAUDE.md](/beginner-plus/claude-md) לכללי הכתיבה.
- **ערך ב-`settings.json` לא חל:** ההגדרות מתמזגות בין scopes. הגדרות מנוהלות חלות קודם, ואחריהן local גובר על project, ו-project גובר על user. משתני סביבה ודגלים בשורת הפקודה יכולים גם הם לדרוס. `/status` מראה אילו מקורות פעילים.

אלה הטעויות הנפוצות ב[רשימת הסיבות של התיעוד](https://code.claude.com/docs/en/debug-your-config#check-common-causes):

| סימפטום | הסיבה | התיקון |
| --- | --- | --- |
| `permissions` או `env` שהגדרת גלובלית לא חלים | ההגדרה נכתבה ב-`~/.claude.json` | הם שייכים ל-`~/.claude/settings.json`. אלה שני קבצים שונים |
| ערך ב-`settings.json` נראה מתעלם | אותו מפתח מוגדר ב-`settings.local.json` | `settings.local.json` גובר על `settings.json` |
| skill לא מופיע ב-`/skills` | הקובץ נמצא ב-`.claude/skills/name.md` | יוצרים תיקייה עם `SKILL.md` בתוכה: `.claude/skills/name/SKILL.md` |
| שרתי MCP מ-`.mcp.json` לא נטענים | הקובץ בתוך `.claude/`, או שהשרתים לא תחת המפתח `mcpServers` | `.mcp.json` יושב בשורש הריפו, והשרתים תחת `mcpServers` |
| שרת MCP של הפרויקט לא מופיע | חלון האישור החד-פעמי נסגר בלי אישור | מריצים `/mcp` ומאשרים את השרת |

### איך בודקים אם תוסף או הגדרה גורמים לבעיה?
מפעילים את Claude Code במצב בטוח:

<CommandBlock>claude --safe-mode</CommandBlock>

המצב הזה מכבה את כל ההתאמות האישיות לסשן: CLAUDE.md,‏ skills,‏ plugins,‏ hooks, שרתי MCP, ופקודות וסוכנים מותאמים. ההתחברות, בחירת המודל, הכלים המובנים וההרשאות עובדים כרגיל. אם הבעיה נעלמת, אחת ההתאמות היא הסיבה, ומשתמשים בפקודות מהטבלה למעלה כדי למצוא איזו. hooks ומדיניות הגדרות שהארגון מנהל עדיין חלים גם במצב הזה.

## מה עושים כשההתחברות נכשלת?
כשהסיבה לא ברורה, [התחברות מחדש נקייה](https://code.claude.com/docs/en/troubleshoot-install#reset-your-login) פותרת את רוב המקרים:

<StepList>

1. מריצים `/logout` כדי להתנתק לגמרי.
2. סוגרים את Claude Code.
3. מפעילים מחדש עם `claude` ומשלימים את ההתחברות.

</StepList>

אם הדפדפן לא נפתח לבד בזמן ההתחברות, לוחצים `c` כדי להעתיק את כתובת ה-OAuth, ומדביקים אותה בדפדפן.

שתי שגיאות שכדאי להכיר:

- **`This organization has been disabled` למרות מנוי פעיל:** משתנה הסביבה `ANTHROPIC_API_KEY` דורס את המנוי. זה קורה לרוב כשמפתח ישן מפרויקט קודם עדיין מוגדר בקובץ ה-profile של ה-shell. מסירים את המשתנה ובודקים עם `/status` איזו שיטת התחברות פעילה.
- **`403 Forbidden` אחרי התחברות:** במנוי Pro או Max בודקים ש[המנוי פעיל](https://claude.ai/settings). בחשבון Console בודקים שהוגדר לך תפקיד "Claude Code" או "Developer". מאחורי proxy ארגוני, ה-proxy עלול להפריע לבקשות.

## מה אומרות שגיאות ה-API הנפוצות?
רוב השגיאות בזמן עבודה מגיעות מה-API. Claude Code [מנסה שוב אוטומטית](https://code.claude.com/docs/en/errors#automatic-retries) תקלות זמניות עד 10 פעמים לפני שהוא מציג שגיאה. כלומר, כשאתה רואה שגיאה, הניסיונות החוזרים כבר נעשו.

| מה רואים | מה זה אומר | מה עושים |
| --- | --- | --- |
| `API Error: 500 Internal server error` | תקלה זמנית בצד השרת. לא קשורה לפרומפט, להגדרות או לחשבון | מחכים דקה ושולחים שוב. בודקים את [status.claude.com](https://status.claude.com) |
| `API Error: Repeated 529 Overloaded errors` | ה-API בעומס אצל כל המשתמשים. לא נספר במכסה שלך | מנסים שוב בעוד כמה דקות, או מחליפים מודל עם `/model` |
| `API Error: Request rejected (429)` | הגעת למגבלת הקצב של מפתח ה-API או של פרויקט הענן | `/status` כדי לוודא איזה credential פעיל. `ANTHROPIC_API_KEY` שנשאר בסביבה יכול לעקוף את המנוי |
| `You've hit your session limit` | נגמרה מכסת השימוש של המנוי עד זמן האיפוס | מחכים לזמן שמופיע בהודעה. `/usage` מציג מגבלות וזמני איפוס |
| `Not logged in · Please run /login` | אין פרטי התחברות תקפים לסשן | מריצים `/login` |
| `Unable to connect to API` | החיבור לשרת לא הצליח: אין אינטרנט, VPN חוסם או proxy לא מוגדר | בודקים גישה עם `curl -I https://api.anthropic.com`. מאחורי proxy מגדירים `HTTPS_PROXY` |
| `Context limit reached · /compact or /clear to continue` | השיחה והקבצים המצורפים חורגים מחלון ההקשר | `/compact` או `/clear`, ו-`/context` כדי לראות מה ממלא את החלון |

<Callout type="tip">
אחרי שגיאת 500 ההודעה שלך עדיין נמצאת בשיחה. במקום להדביק פרומפט ארוך שוב, אפשר לכתוב `try again`.
</Callout>

את כל השגיאות, עם ההסבר המלא לכל אחת, מוצאים ב[מדריך השגיאות הרשמי](https://code.claude.com/docs/en/errors). הודעות מסוימות משתנות לפי ספק או תוכנית, אז משווים לנוסח שמופיע אצלך.

## מה עושים כש-Claude Code איטי או נתקע?
Claude Code עלול לצרוך הרבה משאבים כשהוא מעבד בסיסי קוד גדולים. לפי התיעוד:

- **צריכת CPU או זיכרון גבוהה:** מריצים `/compact` באופן קבוע כדי להקטין את ההקשר, סוגרים ומפעילים מחדש בין משימות גדולות, ומוסיפים תיקיות build גדולות ל-`.gitignore`. אפשר גם להפעיל עם `claude --safe-mode` כדי לבדוק אם plugin, שרת MCP או hook גורמים לבעיה.
- **אזהרת זיכרון קריטית:** מופיעה כשהזיכרון של סשן עובר 2.5GB. מפעילים מחדש את Claude Code ומריצים `claude --continue` כדי להמשיך את השיחה בתהליך חדש.
- **פקודה נתקעת:** לוחצים `Ctrl+C` כדי לנסות לבטל. אם אין תגובה, סוגרים את הטרמינל ומפעילים מחדש. השיחה לא הולכת לאיבוד: `claude --resume` באותה תיקייה מחזיר אותך אליה.
- **`Autocompact is thrashing`:** הדחיסה האוטומטית הצליחה, אבל קובץ או פלט גדול מילא שוב את ההקשר כמה פעמים ברצף. מבקשים מ-Claude לקרוא את הקובץ הגדול בחלקים קטנים, או מריצים `/compact` עם מיקוד שמשמיט את הפלט הגדול, למשל `/compact keep only the plan and the diff`.

## איפה נמצאים הלוגים?
כשהבדיקות הרגילות לא מספיקות, מפעילים רישום debug. יש שתי דרכים:

- **בתוך סשן פעיל:** מריצים `/debug` עם תיאור הבעיה. הפקודה מפעילה רישום debug לסשן ומבקשת מ-Claude לאבחן לפי הלוג.
- **מההתחלה:** מפעילים סשן עם הדגל `--debug`:

<CommandBlock>claude --debug</CommandBlock>

לפי [מדריך דיבוג ההגדרות](https://code.claude.com/docs/en/debug-your-config#check-mcp-servers), לוג ה-debug נשמר ב-`~/.claude/debug/<session-id>.txt`. לבעיות בשרתי MCP מפעילים `claude --debug=mcp` וקוראים בלוג את הפלט של השרת.

## איך מדווחים על תקלה?
אם שום דבר לא עזר, יש ארבעה צעדים:

<StepList>

1. מריצים `/doctor` לבדיקת ההגדרות ו-`/mcp` לבדיקת שרתי MCP.
2. מריצים `/feedback` בתוך Claude Code כדי לדווח ל-Anthropic ישירות. [הפקודה שולחת את התמליל ותיאור של הבעיה](https://code.claude.com/docs/en/errors#report-an-error), ומציעה גם לפתוח issue ב-GitHub.
3. בודקים ב-[ריפו של Claude Code ב-GitHub](https://github.com/anthropics/claude-code) אם הבעיה כבר ידועה.
4. שואלים את Claude עצמו. יש לו גישה מובנית לתיעוד של Claude Code.

</StepList>

<Callout type="warning">
בעיות של חשבון, חיוב או מנוי לא פותרים ב-Claude Code. נכנסים ל-[claude.ai](https://claude.ai) (משתמשי Console: [platform.claude.com](https://platform.claude.com)), לוחצים על ראשי התיבות שלך בפינה השמאלית התחתונה ובוחרים **Get help**.
</Callout>
