Claude Code שומר כל שיחה כסשן מקומי שקשור לתיקיית הפרויקט. `claude --continue` מחזיר אותך לשיחה האחרונה, ו-`claude --resume` או `/resume` פותחים רשימה לבחירה. נותנים לסשן שם עם `/rename`, מפצלים אותו עם `/branch` כדי לנסות גישה אחרת, ומייצאים אותו עם `/export`.

## למה זה חשוב
[כל סשן חדש מתחיל עם חלון הקשר נקי](https://code.claude.com/docs/en/how-claude-code-works#work-with-sessions), בלי השיחות הקודמות. אם סגרת את הטרמינל באמצע משימה ופתחת `claude` מחדש, Claude לא זוכר על מה דיברתם. כשחוזרים לסשן הקודם, היסטוריית השיחה המלאה חוזרת איתו, כולל קריאות לכלים והתוצאות שלהן. זה חוסך הסבר מחדש, ומאפשר לעבוד על כמה משימות במקביל ולעבור ביניהן.

Claude Code שומר את השיחה ברציפות תוך כדי עבודה, כך שאפשר לחזור אליה גם אחרי יציאה או אחרי `/clear`.

## איך חוזרים לסשן קודם?
יש כמה דרכים, לפי מה שאתה יודע על הסשן:

| פקודה | מה היא עושה |
| --- | --- |
| `claude --continue` | פותחת מחדש את השיחה האחרונה בתיקייה הנוכחית |
| `claude --resume` | פותחת את בוחר הסשנים (session picker) |
| `claude --resume <name>` | חוזרת ישירות לסשן עם השם הזה |
| `claude --from-pr <number>` | פותחת את הבוחר, מסונן לסשנים שקשורים ל-pull request הזה |
| `/resume` | עוברת לשיחה אחרת מתוך סשן פעיל |

המקרה הנפוץ ביותר: יצאת מ-Claude Code וחוזר לאותה תיקייה. מריצים:

<CommandBlock>claude --continue</CommandBlock>

<Callout type="note">
סשנים שנוצרו עם `claude -p` (מצב לא אינטראקטיבי) או עם ה-Agent SDK לא מופיעים בבוחר ו-`claude --continue` מדלג עליהם. אפשר עדיין לחזור אליהם עם `claude --resume` ומזהה הסשן (session ID).
</Callout>

## מה חוזר כשממשיכים סשן?
סשן שחוזרים אליו משחזר את השיחה ואת המצב שנשמר בה:

- **היסטוריית השיחה** המלאה, כולל קריאות לכלים והתוצאות שלהן.
- **המודל** שהסשן עבד איתו, ברוב המקרים. לפרטים על בחירת מודל ראה את [דף הגדרות המודל הרשמי](https://code.claude.com/docs/en/model-config).
- **מצב ההרשאות** (permission mode), כשחוזרים מהטרמינל עם `claude --continue` או עם שם או מזהה. יש לזה חריגים: למשל, סשן שהסתיים ב-plan mode חוזר במצב שסשן חדש היה מתחיל בו. דרך הבוחר או `/resume` מצב ההרשאות לא משוחזר.

לא כל דגל שהועבר בהפעלה המקורית חוזר. אם הסשן נפתח עם דגלים כמו `--add-dir` או `--settings`, מעבירים אותם שוב. הגדרות שנמצאות בקובצי `settings.json` נקראות מחדש בכל הפעלה, אז אותן לא צריך להעביר.

## איך עובד בוחר הסשנים?
מריצים `/resume` בתוך סשן, או `claude --resume` בלי ארגומנט. כברירת מחדל נפתחת רשימה של הסשנים מה-worktree הנוכחי, ואפשר להרחיב אותה בקיצורי מקלדת. כל שורה מציגה את שם הסשן, או כותרת שנוצרה אוטומטית, וגם כמה זמן עבר מהפעילות האחרונה, את ה-git branch ואת גודל הקובץ.

קיצורי המקלדת העיקריים:

| מקש | פעולה |
| --- | --- |
| `↑` / `↓` | מעבר בין סשנים |
| `Enter` | חזרה לסשן המסומן |
| `Space` | תצוגה מקדימה של תוכן הסשן |
| `Ctrl+R` | שינוי שם לסשן המסומן |
| `/` או כל תו מודפס אחר מלבד `Space` | חיפוש וסינון |
| `Ctrl+A` | הצגת סשנים מכל הפרויקטים במחשב |
| `Ctrl+B` | סינון לסשנים מה-git branch הנוכחי |
| `Esc` | יציאה מהבוחר או ממצב חיפוש |

## איך נותנים לסשן שם?
שם תיאורי עוזר למצוא את הסשן בבוחר ולחזור אליו ישירות. זה חשוב במיוחד כשעובדים על כמה משימות במקביל.

- **בהפעלה:** `claude -n auth-refactor`
- **בתוך סשן:** `/rename auth-refactor`. השם מופיע גם בשורת ההקלדה.
- **מהבוחר:** מסמנים סשן ולוחצים `Ctrl+R`.

אחרי שנתת שם, חוזרים אליו כך:

<CommandBlock>claude --resume auth-refactor</CommandBlock>

אם לא נתת שם, Claude Code יוצר לסשן כותרת קצרה שמסכמת את הפרומפט הראשון. היא מופיעה בבוחר, ואפשר להעביר גם אותה ל-`claude --resume` או ל-`/resume`.

## איך מפצלים סשן כדי לנסות גישה אחרת?
פיצול (branch) יוצר עותק של השיחה עד עכשיו ומעביר אותך אליו. הסשן המקורי נשאר כמו שהוא, כך שאפשר לנסות כיוון אחר בלי לאבד את הדרך שבה הלכת.

מתוך סשן, מריצים `/branch` עם שם, או בלי שם:

```text
/branch try-streaming-approach
```

בלי שם, Claude Code קורא לענף החדש על שם הפרומפט הראשון בשיחה. ההודעה שמאשרת את הפיצול מציגה שני מזהי סשן: של הענף החדש שבו אתה נמצא ושל המקורי. חוזרים למקורי עם `/resume` והשם או המזהה שלו.

משורת הפקודה משלבים את `--fork-session` עם `--continue` או `--resume`:

```bash
claude --continue --fork-session
```

| | המשך (`--continue`, `--resume`) | פיצול (`/branch`, `--fork-session`) |
| --- | --- | --- |
| מזהה הסשן | אותו מזהה | מזהה חדש |
| הודעות חדשות נכתבות אל | הסשן הקיים | העותק החדש |
| הסשן המקורי | ממשיך להשתנות | נשאר בלי שינוי |

<Callout type="warning">
אם פותחים את אותו סשן בשני טרמינלים בלי פיצול, ההודעות משניהם מתערבבות בשיחה אחת. כדי לעבוד במקביל על אותה נקודת התחלה, מפצלים.
</Callout>

פיצול הוא לא ביטול שינויים. כדי לחזור לנקודה קודמת בתוך אותו סשן, כולל הקוד, משתמשים ב-checkpoints. על זה יש [שיעור נפרד](/beginner-plus/checkpointing).

## מה ההבדל בין /clear ל-/compact?
שתי הפקודות מנקות מקום בחלון ההקשר בלי לצאת מ-Claude Code:

- **`/clear`** מתחיל שיחה חדשה עם הקשר ריק. השיחה הקודמת נשמרת, וחוזרים אליה עם `/resume`.
- **`/compact`** מחליף את ההיסטוריה בסיכום. אפשר להוסיף הנחיה על מה להתמקד, למשל `/compact focus on the API changes` ([דוגמה מהתיעוד](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)).
- **`/context`** מציג מה תופס כרגע את חלון ההקשר.

על מתי לנקות ומתי לסכם, ומה זה עושה לעלות, יש [שיעור על עלויות והקשר](/beginner-plus/costs-context).

## איך מייצאים סשן?
מריצים `/export`. נפתח תפריט שמאפשר להעתיק את השיחה ללוח (clipboard) או לשמור אותה כקובץ טקסט, עם ההודעות ותוצאות הכלים בפורמט קריא. אפשר גם להעביר שם קובץ, ואז הייצוא נכתב ישירות אליו בלי התפריט.

<CommandBlock>/export</CommandBlock>

זה שימושי כדי לשתף שיחה עם חבר צוות, או לשמור תיעוד של משימה.

## איפה הסשנים נשמרים?
כברירת מחדל Claude Code שומר כל סשן כקובץ JSONL בנתיב:

```text
~/.claude/projects/<project>/<session-id>.jsonl
```

`<project>` הוא נתיב תיקיית העבודה, כשכל תו שאינו אות או ספרה מוחלף ב-`-`. כל שורה בקובץ היא אובייקט JSON של הודעה, שימוש בכלי או מטא-דאטה.

- **שמירה:** הקבצים נמחקים אוטומטית אחרי 30 יום. משנים את זה בהגדרה `cleanupPeriodDays` ב-`settings.json`.
- **קריאה מסקריפטים:** מבנה הקבצים פנימי ומשתנה בין גרסאות. סקריפט שקורא אותם ישירות עלול להישבר. עדיף `/export`, או הממשקים לסקריפטים שמתוארים ב[דף הרשמי](https://code.claude.com/docs/en/sessions#access-conversations-from-scripts).

<Callout type="tip">
הקבצים האלה שמורים על המחשב שלך. אפליקציית הדסקטופ, claude.ai/code ותוסף VS Code מחזיקים כל אחד היסטוריית סשנים משלו. השיעור הזה עוסק ב-CLI.
</Callout>

## דוגמה מעשית
אתה עובד על שינוי במערכת ההתחברות, ורוצה לחזור אליו מחר:

<StepList>

1. בתחילת העבודה נותנים שם: `/rename auth-refactor`.
2. באמצע, רוצים לנסות פתרון אחר בלי לאבד את מה שיש: `/branch try-jwt`.
3. הניסיון לא הצליח. חוזרים לסשן המקורי עם `/resume auth-refactor`.
4. למחרת, מאותה תיקייה, מריצים `claude --resume auth-refactor` וממשיכים מאותה נקודה, עם כל ההקשר.

</StepList>
